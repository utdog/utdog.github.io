前端入门：HTML 标签与页面结构

前言

Python 写完了，最后一门课是前端。课表排了 22 天：day01–day11 讲 HTML 和 CSS，day12 开始讲 JavaScript，day20 讲 jQuery，最后一天用这些知识做一个贪吃蛇。

这篇是第一部分的 HTML 部分。学完最大的感受是：HTML 不是编程语言，是描述性的标记语言——它没有变量、没有循环、没有判断，只负责告诉浏览器「这段文字是标题、这是一张图、这里是一个列表」。真正决定网页好不好看的，是后面要学的 CSS。

一、网页的三个层次

课件一上来先讲 Web 标准。网页可以拆成三层：

层次 技术 负责什么
结构（Structure） HTML 网页的整体结构，有哪些内容
表现（Presentation） CSS 外观：颜色、大小、位置、字体
行为（Behavior） JavaScript 动效、交互、动画

课件里有个很直观的比喻：结构是身体，表现是打扮，行为是吸引人的举止。还有个实验值得做一遍——打开京东然后禁用 JS，看看页面剩下什么、少了什么，三层各自负责哪一块一目了然。

Web 标准不是某一个标准，而是 W3C 等标准化组织制定的一系列标准的集合（HTML 标准、CSS 标准、ECMAScript 标准等）。

二、HTML 骨架

新建一个 .html 文件，第一件事是把骨架敲出来（输入法一定要切到英文半角状态）：

每一行的作用注释里都写了。几个容易忽略的点：

  • <!DOCTYPE html> 告诉浏览器按 HTML5 规范解析；HTML5 之前这里要写一长串规范地址。
  • charset="UTF-8" 一定要写，否则中文会乱码。
  • lang 属性决定浏览器会不会自动弹翻译框：en 表示这是个英文网页（不管你写的是不是英文），浏览器打开会提示翻译；zh-cn 表示中文网页，不会弹。面向国内用户就写 zh-cn。

标签之间只有两种关系，缩进规范也是照它来的：

  • 嵌套关系（父子）：<head><title></title></head>，子元素缩进一个 Tab；
  • 并列关系（兄弟）：<head></head><body></body>，上下对齐。

三、书写规范

课件列了六条，属于「一开始就养成习惯」的：

  1. 标签、属性名、符号全部在英文半角下小写；
  2. 养成写注释的习惯 <!--注释-->；
  3. id、class 必须以字母开头；
  4. 所有双标签必须闭合；
  5. 按层次结构用 Tab 缩进；
  6. 属性值必须带引号（单双引号都行，看团队规范）。

四、head 里的 meta

meta 写在 head 中，是个辅助标签，属性不同含义不同：

keywords 和 description 可以在百度搜索结果里对应着看：结果标题下面是描述，来源等信息之外就是靠这些 meta 提供的。这也是我自己博客每篇文章都补 description 的原因——它直接决定搜索结果里那句摘要。

五、最常用的结构标签

div

div 用于把文档划分为独立的、不同的部分，网页的主体骨架一般由它搭建（division，分开、分隔）。HTML5 之后有很多语义化新标签可以替代它搭骨架。

标题 h1~h6

h1~h6 表示标题，默认有不同程度的加粗和放大。一个网页中 h1 最好有且仅有一个（有利于 SEO），其他 h 标签可以出现多次。

段落 p

p 里放一段文字。注意：p 标签中不可以放 div 等块级标签，这会导致浏览器把 p 分隔成两个。这是初学者最常见的错误之一。

其他常用标签

标签 作用 备注
b / strong 加粗 b 只是视觉加粗，strong 还能被搜索引擎识别
i / em 斜体 同上，em 有语义
br 换行 单标签
hr 分隔横线 单标签
sup / sub 上标 / 下标
del 删除线
pre 预格式化 按编辑器里文字的摆放格式显示

六、列表

三种列表，各有各的语义，别乱用：

  • ul 的 type 可取值 disc（默认实心圆点）/ circle（空心圆）/ square（实心方块）；
  • ol 的 type 可取值 1（数字）/ A、a（字母）/ I、i（罗马数字）；
  • 但更推荐用 CSS 改，符合「结构与样式分离」；
  • 列表项里不一定只能放文字，可以套其他标签；列表之间允许互相嵌套。

英文对照能把语义记住：unordered list（无序）、ordered list（有序）、definition list / term / description（定义列表 / 项 / 说明）。

七、超链接 a

target 的取值：

  • _blank 新标签页打开；
  • _new 新标签页打开，但所有 _new 只会共用一个新标签页；
  • _self 默认，当前标签页打开。

锚点也可以配合 name 属性用，只要 href="#abc" 对应到 <a name="abc"> 所在的位置即可（anchor，锚）。

八、图片 img

img 是单标签，HTML5 规范中不要求用 / 结尾。四个重要属性：

  • src：图片路径。分两种写法——
    • 相对路径：以 ./、../ 开头，或直接以文件名 / 目录名开头；
    • 绝对路径：从根目录出发的路径，或完整的网络地址。
      所有需要写路径的地方（比如 a 的 href）都适用这两种写法。
  • width / height：指定显示尺寸。写上之后浏览器加载时能给图片预留空间，避免布局跳动。
  • alt：告诉搜索引擎这张图是什么；当 src 出错时，alt 的文字会显示出来，让用户不至于看到一片空白。
  • title：鼠标移到图片上显示提示文字（title 不是 img 独有的，大部分标签都能用）。

课件里有句话值得单独记下来：

即使使用 width 和 height 缩小图片，也仅仅是视觉上的缩小，浏览器还是要加载原始图片资源（并不能减轻请求压力）。所以有缩放需求时，应当提前用图片处理软件处理好再引入。

这条我在自己博客上踩过反面教材——原站点 190 MB，单张封面图 2559px、10 MB，靠 CSS 缩小完全没用。后来把 25 张封面统一压到 1600px 的 JPEG，站点直接降到 14.6 MB。图片该在引入之前处理，而不是在页面里缩放。

课件说得很实在：很多特殊字符不用实体也不会出错，实体的意义在于为键盘上不好打出来的字符提供替代输入方式。完整列表可以查 w3school 的 HTML 实体符号手册。

十、语义化

每个标签都有对应的英文原词和含义，这就是 HTML 标签的语义化。为什么重要：

  • 没有样式的时候也能看出网页大致结构；
  • 有利于 SEO；
  • 增强用户体验；
  • 有利于团队协作。

所以写代码要遵循语义化：放一段文字就用 p，不要用 div；展示有先后顺序的步骤就用 ol，不要用 ul。

十一、表单

表单是「用户填数据 → 提交给后端」的区域。form 只是一个大区域，真正采集数据的是里面一个个表单控件。

  • action：提交到哪个地址；
  • method：提交方式，一般 get 或 post；
  • target：后端返回的新页面在哪打开，取值同 a 标签；
  • name：表单名。

所有控件都必须有 name 和 value 属性（采集数据的键值对），并且除了单选按钮之外，所有控件的 name 都不能相同。

input 的九种类型

两个常用属性：

  • checked：单选 / 多选时指定默认选中项；
  • disabled：规定控件禁止使用。

label：让文字也能点

十二、表格

  • table 定义表格，tr 定义行（内容都写在行里），th 是列标题（默认加粗），td 是每一项；
  • border 给单元格加边框，但只能控制 table 的边框宽度；用 CSS 的 border-collapse: collapse; 让相邻单元格边框合并才是常见做法；
  • cellpadding 控制单元格内边距（会受 CSS 影响），cellspacing 控制单元格间隙（可用 CSS border-spacing 代替），align 控制文字对齐；
  • 单元格合并：rowspan 纵向跨行、colspan 横向跨列；
  • 其他标签：caption 表格标题、thead 表头、tbody（即使不写也会自动加）、tfoot 表尾。

课件提到早年很多页面用 table 布局，现在基本不用了——太规整、不符合多样化布局、对 SEO 极不友好、维护成本高。但 table 的默认特性很有意思，理解了能解决实际问题：

一行中单元格的高度以最大的为准，一列中单元格的宽度以最大的为准；
一行中单元格的宽度按内容多少分配，若有一个单元格设了宽度，剩下的宽度平分给其他没设置的。

利用这个特性可以做「左边宽度固定、右边自适应剩余宽度」——不用浮动、不用定位：

display: table / table-row / table-cell 就是让普通元素拥有表格的这些特性。

小结

HTML 这一部分要记的其实不多，但有几条是后面写 CSS 和 JS 的前提：

  1. 骨架 + charset + lang 三件套先写全；
  2. 标签看语义选，别全都用 div；
  3. id 唯一、class 可复用，id/class 必须以字母开头（id 重名还会影响后面 JS 获取元素）；
  4. 表单控件必须有 name 和 value，这是数据能不能提交上去的关键；
  5. 图片在引入之前就处理好尺寸和体积，不要指望 CSS 缩小。
