CSS 基础：选择器、盒模型与布局

前言

上一篇写完了 HTML 的「结构」，这篇写「表现」。

HTML 只描述内容是什么，页面长什么样全靠 CSS。课件用了 6 天讲这部分（day02 到 day11），顺序很讲究：先学会怎么选中元素（选择器），再理解元素是个什么形状（盒模型），然后才是怎么把它们排起来（浮动 / 定位 / flex）。这个顺序不能乱——浮动算宽度、算间距全是在算盒子。

一、CSS 写在哪

三种写法：

样式表 优点 缺点 使用情况
行内样式表 书写方便，权重高 没有实现结构与样式分离，不便于维护，不能重复利用 极少，单个标签需要单独样式时
内部样式表 部分结构与样式分离，较便于维护 没有彻底分离，不能重复利用 一般，代码量少且不需复用时
外部样式表 完全实现结构与样式分离，可重复利用 代码量少时引入反而麻烦 最多，推荐

二、选择器（初级）

写法 名称 举例
* 通配选择器 *{ margin:0; padding:0; }
标签名 元素选择器 div{ width:50px; height:50px; }
.class名 class 选择器 .nav{ width:20px; }
#id名 id 选择器 #header{ width:50px; }
父 子 孙…… 后代选择器 #header div p{ margin:10px; }

id 与 class 的区别和命名规范（课件强调，后面写 JS 时会直接影响）：

  • id 命名唯一：单个标签不允许有多个 id，同页面不能出现重复 id——id 重名会影响 JS 获取标签；
  • class 命名不唯一：一个标签可以有多个 class，不同标签可以用相同 class；
  • 命名允许大写字母、小写字母、数字、-，必须以字母开头，单词一般小写；
  • 见名知意，不允许单个字母做名字；单词之间用 - 连接或驼峰，看公司规范。

权重（优先级）

同一个标签被多个选择器赋予了相同的属性、值却不一样时，按优先级决定：

.info 和 p 都选中了这个 p，最终颜色由优先级决定：

!important > 行内 > id > class | 属性 | 伪类 > 标签 > 通配符 | 兄弟 | 相邻兄弟 | 子代 > 继承

三条判断规则：

  1. 先比级别；
  2. 级别一样，比各级别选择器出现的次数；
  3. 权重完全一样时，以最后出现的为准。

三、选择器（高级）

写法 名称 举例
选择器, 选择器 组合选择器（多个选择器共用样式） #nav p,#tab a{ font-size:12px; }
父 > 子 子元素选择器（只会选儿子） div>a{ color:red; }
兄 + 弟 相邻兄弟选择器（紧挨着哥哥的弟弟） p + a{ color:red; }
兄 ~ 弟 关联选择器（元素后续的元素） p ~ a{ color:red; }
[attr] 属性选择器（拥有该属性） [title]{ color:red; }
[attr=val] 属性选择器（值等于 val） [target=_blank]{ color:red; }
[attr*=val] 属性选择器（值包含 val） [src*=baidu]{ border:5px solid pink; }
[attr$=val] 属性选择器（值以 val 结尾） [src$=jpg]{ border:5px solid pink; }
[attr|=val] 属性选择器（值以 val 开头） [class|=nav]{ background:pink; }
选择规则1选择规则2 复合选择器 div.nav.left{ width:100px; } 有 nav 和 left 类名的 div

伪类选择器

状态类——元素在特定状态下改变样式：

写法 介绍 举例
:hover 鼠标悬停 a:hover{color:pink;}
:link 未被访问的链接（特指 a） a:link{color:red;}
:visited 被访问过的链接（特指 a） a:visited{color:blue;}
:active 被点击按下的状态 a:active{color:green;}
:focus 获得焦点 input:focus{border:1px solid blue;}
:checked 单选/多选被勾选 input:checked{background-color:#aaa;}

:hover、:active 不只能用在 a 标签上，而且 :hover 最常用最重要；伪类后面还能继续选择元素：

结构类——按位置选中元素：

写法 介绍
E:nth-child(n) E 元素父级的第 n 个子元素（该子元素还必须满足 E 的选择规则，不满足则一个都选不中）
E:nth-of-type(n) E 元素父级的第 n 个 E 元素，无视其他元素
E:first-child / E:last-child 第一个 / 最后一个子元素（同样要求满足 E 的规则）

n 可以是数字、odd（奇数）、even（偶数）或表达式：

对应的「倒着数」版本是 :nth-last-child(n) 和 :nth-last-of-type(n)。

这两个的差别建议亲手试一次：p:nth-child(2) 要求"父级第 2 个子元素恰好是 p"，父级第 2 个是 div 时就选不中；p:nth-of-type(2) 只数 p。表格隔行换色用 tr:nth-child(even) 更直观，因为 tr 的兄弟几乎只有 tr。

伪元素选择器

伪类是「某种情况下加一个虚拟类名」，伪元素则是「创建一个虚拟元素」：

写法 介绍 举例
E::before 在 E 元素最前面加一个额外子元素 #wrap::before{content:"Hello World!"}
E::after 在 E 元素最后面加一个额外子元素 #wrap::after{content:"Hello World!"}
  • 必须拥有 content 样式才会生效；
  • 创建出来的子元素是行内元素；
  • ::after 常用来清除浮动（下面盒模型部分会用到）；
  • content 除了写文字，还能用 url 指定图片。

其他不常用的：E::first-line（首行样式）、E::selection（用户复制选中部分）。

四、盒模型

在 HTML 中每个标签都是一个长方形，包含内容区 content、内填充 padding、边框 border、外边距 margin，所以叫盒模型。

内容区

由内容撑开，或用 width / height 指定：

内填充 padding

相当于内容四周的填充物（泡沫、报纸、气垫）。不接收负值，接收长度值或百分比。

复合属性按值的个数表达不同含义，这是最容易记混的地方：

两个重要特性：内边距部分会显示盒子的背景；内边距会撑大盒子的整体大小，但不会影响内容的大小。

边框 border

包裹在 padding 外层：

常用边框线类型：none（无边框）、solid（实线）、dotted（点状）、dashed（虚线）、double（双线）。

也可以按方向拆开，甚至进一步拆成 width/style/color：

外边距 margin

盒子与其他盒子之间的间距，在边框外层，不会显示盒子背景。取值规则和 padding 类似，但有两点不同：

  • margin 允许负值；
  • 多了 auto，可以用来把盒子在父级中左右居中（margin: 0 auto;）。

标准盒模型 vs 怪异盒模型

区别在于 width / height 到底管哪一部分：

  • 标准盒模型（box-sizing: content-box;，默认）：width/height 只表示 content 内容区；
  • 怪异盒模型（box-sizing: border-box;）：width/height 包含 content + padding + border。

这两个的差别在写页面时非常关键：设计图给的宽度是「盒子总共多宽」，而默认的标准盒模型会把 padding 和 border 加在宽度外面，于是加了边框就撑破布局。很多团队直接在项目开头写 *{ box-sizing: border-box; }，就是这个原因。

很多标签自带边距或样式（目的是不写 CSS 时看起来不至于太糟），但按设计图写页面时它们会干扰布局，所以要清掉：

*{} 的问题在于它作用于页面上所有元素（包括伪元素和自己写的每一个小图标），会带来不必要的性能开销和「怎么都改不动」的样式覆盖麻烦。

六、浮动

普通文档流

浏览器默认规定块元素在父元素内的排列规则：

  1. 从上往下排列；
  2. 从左开始排列；
  3. 一个块元素占一行。

浮动之后

给元素加 float: left / right，它就脱离文档流，可以水平排布，后面的元素会往上占据空出来的位置。

  • box1 浮动、box2 不浮动：box2 会钻到 box1 下面（被盖住一部分）；
  • box1、box2 都浮动：两者水平排布，box3 往上占位置；
  • 三个都浮动但父级宽度不够：第三个换行显示；如果第一个比第二个高，第三个还会被"卡住"；
  • 一个向左浮动、一个向右浮动：各自按方向排列；
  • 图文环绕：img 加 float:left 后，文字会环绕在图片右侧（不加浮动时图片底端与第一行文字底端对齐）。

父级高度塌陷（重点）

父元素没设高度时，高度由文档流内容撑开；子元素一旦浮动就脱离文档流，父级高度不会被撑开，后续布局会全乱。四种解法：

补充

  • 元素浮动之后不再支持 margin: auto，只支持 margin 的确切值；
  • 横向布局推荐用浮动而不是 inline-block：inline-block 布局的基线对齐处理麻烦，而且标签间的空格会被解析显示在页面上，浮动没有这两个问题；
  • list-style: none; 清除 ul/ol 的默认项目符号；
  • min-width / max-width 控制最小/最大宽度。

七、定位

position 让元素从文档流中取出，然后用方位属性 left / top / right / bottom 精准控制位置。

值 描述
static 默认值。没有定位，元素出现在正常流中（忽略 top/left/z-index 声明）
relative 相对定位，相对于其正常位置定位
absolute 绝对定位，相对于 static 以外的第一个父元素定位
fixed 固定定位，相对于浏览器窗口定位

relative 的特点

不会脱离文档流；
不影响元素本身的任何特性；
如果不加方位词偏移，那么没有任何影响。

相对定位能让元素保持原文档流位置的同时，相对于原位置偏移——所以它最常用来给内部的绝对定位元素当"定位父级"。

absolute 的特点

脱离文档流；
元素宽高默认值变为 0（所以必须给宽高或由内容撑开）；
找不到最近的定位父级则相对于 body 标签；
一般配合相对定位使用；
margin: auto 失效。

两个细节容易踩：

  • 方位属性初始值不是 0，而是 auto；
  • left、top 的优先级比 right、bottom 高——同时写 left 和 right 时，以 left 为准。

fixed 的特点

脱离文档流；元素宽高默认值为 0；margin: auto 失效；相对于浏览器可视区偏移。

八、图标字体（阿里图标）

页面上那些小图标（放大镜、购物车、箭头）如果用图片做，会有两个问题：放大就糊、改颜色要重新导出。图标字体的思路是：把图标定义成字体，通过引入字体来展示——此时图标相当于一个文字，支持文字对应的所有样式（颜色、字号、阴影、旋转都能用）。

使用步骤：

  1. 打开阿里图标库 iconfont.cn 并登录；
  2. 搜索并选择需要的图标加入购物车；
  3. 全部选完后点右上角购物车，下载代码；
  4. 打开下载文件里的 demo 页面——里面详细介绍了三种引入方式、各方式优缺点和对应代码，选一种引入自己项目即可。

九、flex 伸缩布局（CSS3）

CSS3 在布局上做了很大改进，伸缩布局对块级元素的排列变得非常灵活，在响应式开发中作用极大。先建立三个概念：

  • 主轴：Flex 容器的主轴用来配置 Flex 项目，默认是水平方向；
  • 侧轴：与主轴垂直的轴，默认是垂直方向；
  • 方向：默认主轴从左向右，侧轴从上到下。

主轴和侧轴不是固定的，通过 flex-direction 可以互换。

属性 作用 常用值
flex 子项目在主轴的缩放比例 不指定则不参与伸缩分配
min-width / max-width 最小 / 最大宽度 min-width: 280px
flex-direction 调整主轴方向 row（默认水平）、column（垂直）、row-reverse、column-reverse
justify-content 主轴对齐（水平对齐） flex-start、flex-end、center、space-between、space-around
align-items 侧轴对齐（单行垂直对齐） stretch（默认，拉伸）、center（垂直居中）、flex-start、flex-end
flex-wrap 是否换行 nowrap（默认，不换行则压缩显示）、wrap、wrap-reverse
flex-flow direction + wrap 的简写 flex-flow: column wrap;
align-content 多行时的垂直对齐 同 justify-content 取值
order 控制子项目排列顺序 整数，默认 0，越小越靠前，可为负

两个容易记错的点：

  • justify-content 管的是主轴（默认水平），align-items 管的是侧轴（默认垂直）；一旦主轴换成 column，它们管的方向也跟着换；
  • align-content 是针对多行的（align-items 只管一行），而且必须同时满足：父元素 display:flex + flex-direction:row + flex-wrap:wrap 才会生效。

课件的记忆口诀是：flex-flow: 排列方向 换不换行;（中间用空格），以及「要明确找出主轴、侧轴、方向，各属性对应的属性值」。

十、踩坑速查

现象 原因 解决
加了 padding/border 后盒子比设计稿宽 默认是标准盒模型，宽高只算 content box-sizing: border-box;
子元素设置了 margin-top，父元素跟着往下跑 父子外边距合并 给父元素加 border-top 或 padding-top
兄弟元素间距比预期小 上下外边距合并取较大者 用 padding 或额外容器控制
父元素高度变成 0，下面的内容压上来 子元素浮动，父级高度塌陷 父元素加 .clear::after 或 overflow:hidden
元素设了 margin:auto 不居中 浮动元素和绝对定位元素不支持 用 flex 或定位居中写法
绝对定位的元素不见了 脱离文档流后宽高默认 0 显式给宽高，或让内容撑开
p:nth-child(2) 选不中 父级第 2 个子元素不是 p 用 p:nth-of-type(2)
::before 没效果 少了 content 加 content: ""
同时写 left 和 right 没按预期 left/top 优先级更高 只写一个方向
z-index 不起作用 元素没有定位 先给 position（非 static）
align-content 没反应 只有一行，或没开换行 加 flex-wrap: wrap

小结

CSS 这部分我最大的体会是「一切都在算盒子」：

  1. 选择器决定改谁——id/class 是基础，权重是判断"为什么改不动"的依据（改不动先看权重，再看 !important 和行内样式）；
  2. 盒模型决定占多大——content/padding/border/margin 从里到外，box-sizing 决定宽度算不算 padding 和 border，外边距还会合并；
  3. 布局决定排哪——浮动是上一代方案（要处理高度塌陷），定位用于层叠和覆盖，flex 是现在最顺手的方案（主轴侧轴想清楚就很好用）。
