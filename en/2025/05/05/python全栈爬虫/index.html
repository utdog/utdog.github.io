python全栈爬虫

前言

爬虫是我学 Python 之后最有成就感的项目类型：几十行代码就能把网页上的数据整理成一张干净的表格。但爬虫也是最容易踩线的技术——所以这篇笔记除了记录 Requests、BeautifulSoup、Scrapy 这些工具的用法，也会写清楚哪些事不能做。所有示例都以公开的、允许抓取的页面为例。

关于本文的范围（补记）

这篇写于我系统看课件之前，是一份通用爬虫概览。后来我按课件《03-爬虫课件-全栈开发班》另写了一组更贴近课堂的系列：《爬虫入门：原理与抓包》、《Requests 与正则表达式》、《解析与存储》、《XPath 与 Fiddler 抓包》、《反爬与验证码》。

对照课件后需要说明清楚——课件的五个阶段没有覆盖本文的这三节：

  • 第五节里的 Playwright（课件讲的是控制台抓包分析 AJAX 接口，没用浏览器自动化）；
  • 第七节 Scrapy 工程化（课件没有讲框架、中间件与分布式）；
  • 第九节 并发提速（课件没有 asyncio / aiohttp 异步爬虫的内容）。

这三部分属于我的自学扩展，不是课程内容；课件同样没有 JS 逆向与字体反爬的讲义。

一、爬虫的基本流程

graph LR
    A[分析目标页面] --> B[发送请求]
    B --> C{拿到响应?}
    C -->|失败| D[重试 / 换代理 / 降速]
    D --> B
    C -->|成功| E[解析 HTML/JSON]
    E --> F[清洗成结构化数据]
    F --> G[入库 CSV / MySQL]

四步走：请求 → 解析 → 清洗 → 存储。写之前先做一件事：打开 robots.txt（https://站点/robots.txt）和目标页面的用户协议，确认没有禁止抓取。

三、解析：从 HTML 里挑出数据

BeautifulSoup：最友好

select 用的是 CSS 选择器语法，和前端学的完全一致：#id、.class、div a、li:nth-child(2)。定位不到元素时优先怀疑两件事：选择器写错了，或者页面是 JS 动态渲染的。

四、翻页、限速与重试

翻页的三种常见形式：URL 里带 page=；POST 请求带页码；下一页的链接藏在 rel="next" 里。先用手点两页，看浏览器地址栏和开发者工具里 Network 面板的变化，再决定用哪种。

五、动态页面怎么办

如果拿到的 HTML 里没有数据，说明内容由 JavaScript 渲染。两条路：

  1. 找接口：打开开发者工具的 Network，筛选 Fetch/XHR，多半能找到返回 JSON 的接口，直接请求它比解析 HTML 省事一百倍。
  2. 上浏览器：Playwright 或 Selenium 驱动真实浏览器，等元素出现再取。

浏览器方案资源占用高、速度慢，能找接口就别开浏览器。

六、反爬的常见形式与正确处理

现象 常见原因 正确做法
403 Forbidden UA / Referer 缺失 补齐请求头，模拟正常浏览器
返回登录页 需要登录态 用 Session 登录，或带合法 Cookie
429 Too Many Requests 请求太快 降并发、加随机间隔、尊重 Retry-After
数据是乱码 编码识别错 resp.apparent_encoding 或手动指定
内容为空 JS 渲染 找接口或上浏览器
需要验证码 风控 停下，不要尝试绕过验证码或破解风控
封 IP 触发风控 降低频率；代理只用于合法场景

需要明确的是：绕过验证码、破解加密参数、伪造身份、抓取非公开数据，都是不该做的事。 技术能做的和应该做的，中间隔着法律和道德。

七、Scrapy：把爬虫工程化

当目标站点有几十个列表页、需要断点续爬和统一去重时，就该上 Scrapy 了。

它的分工很清晰：Spider 定义抓谁和怎么解析，Item/Pipeline 负责清洗和入库，Middleware 统一处理请求头、代理和重试。用 scrapy crawl quotes -O quotes.json 跑一次，输出直接落盘。

十、合规底线

写爬虫前我会先问自己四个问题：

  1. robots.txt 允许吗？用户协议禁止抓取吗？
  2. 数据公开吗？涉及个人信息、付费内容、隐私数据的一律不碰。
  3. 频率会不会影响对方服务？加延迟、限制并发，别做压测式请求。
  4. 拿到的数据怎么用？只做学习统计，不二次分发、不商用。

合规的爬虫是自动化工具，不合规的爬虫是攻击。 这条线不能模糊。

十一、踩坑记录

现象 原因 解决
中文乱码 编码判断错 resp.encoding = resp.apparent_encoding
SSLError 证书校验 优先补证书；verify=False 只用于本地调试
选择器取到 None 元素不存在或结构变了 用 get_text() 前判空，加 try/except
请求一直卡住 没设超时 所有请求加 timeout
第二次跑全是重复数据 没有唯一约束 建唯一索引 + ON DUPLICATE KEY UPDATE
内存暴涨 把几十万条结果堆在 list 里 边爬边写盘，或用生成器
被 429 封 并发太高 降速、加重试、读 Retry-After

小结

爬虫的功夫一半在“请求与解析”，一半在“清洗与存储”——后者才决定数据能不能用。工具上我的顺序是：接口优先 → Requests + BeautifulSoup → 工程化了再上 Scrapy → 页面必须渲染才用浏览器。下一步打算把抓到的数据接进 Django 做可视化，顺便复习一遍 MySQL 的索引优化。
