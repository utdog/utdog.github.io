Python 并发编程：进程、线程与协程怎么选

前言

「同时做多件事」在 Python 里有三种实现：多进程、多线程、协程。这一课的学习路径很顺：先用 Process 开出子进程 → 发现进程间数据不共享，需要 Queue → 用抢票案例看到共享数据会被写坏 → 加锁 → 换多线程，又撞上 GIL → 最后用协程在单线程里做并发。每种方案都是为解决问题而出现的，知道「为什么」比记住 API 重要。

一、先把四个词分清

概念 含义
进程 程序在计算机中的一次执行过程。程序是静态的文件，进程是动态的过程
并发 任务数多于 CPU 核数，靠操作系统的调度算法让多个任务「一起」执行
并行 任务数小于等于 CPU 核数，多个任务真的同时执行
同步 / 异步 同步指一个任务执行完才做下一个；异步指不必等待，可以先做别的

无论是并发还是并行，在用户看来都是「同时」，但真正干活的 CPU 一个时刻只能执行一个任务——并发的本质是快速切换，并行的本质是物理上的同时。

二、多进程：把任务包成函数

创建进程三要素：封装任务函数 → 用 Process 关联 → start() 启动。

几个必须记住的结论（都来自课件）：

  • 子进程会复制父进程的内存空间与代码段，但只执行指定的那个函数；
  • 各个进程执行上互不影响、也没有先后顺序；
  • 进程空间独立，数据不共享（这一点后面会变成一个大坑）；
  • multiprocessing 创建的子进程中无法使用标准输入 input()；
  • 必须写在 if __name__ == '__main__': 里，否则 Windows 上会无限递归创建进程。

三、进程间通信：用队列

进程空间独立，所以需要专门的手段传数据，最常用的是消息队列：在内存里开一块空间，建立队列模型，进程往里面 put、从里面 get。

课件把它总结成一句话：消息队列是用来存储待处理任务的池子，比如「批改试卷」——把试卷全丢进队列，开多个进程/线程一起批。

由此引出经典的生产者消费者模式：生产者和消费者不直接通信，而是通过阻塞队列传递数据，队列起到缓冲区的作用，平衡两边速度。

四、数据竞争：抢票案例为什么要加锁

进程间数据不共享，但如果共享的是一份文件，照样会打架。课程用「抢票」演示：

课件里的一句话总结很到位：共享带来的问题是竞争，竞争带来的问题是混乱。

五、多线程与 GIL

线程是「轻量级的进程」：一个进程可以有多个线程，同一进程内的线程共享该进程的全部资源，创建销毁的开销远小于进程。

但 Python（CPython）有个绕不开的东西：

GIL（全局解释器锁）：CPython 解释器特有，让一个进程中同一时刻只能有一个线程被 CPU 调用。

所以选型原则是：

任务类型 选什么 例子
计算密集型（吃 CPU） 多进程 大量数据计算、图像处理
IO 密集型（等 IO） 多线程 文件读写、网络请求、爬虫

原因是：多线程虽然不能并行跑 Python 字节码，但线程在等待 IO 时会释放 GIL，这期间别的线程可以继续跑；而计算密集型任务没有 IO 等待，多线程就只能排队，还不如直接开进程用满多核。

十、选型速查

方案 并发单位 数据共享 开销 适合
多进程 进程 不共享（要 Queue） 大 计算密集型、需要吃满多核
多线程 线程 共享（要加锁） 中 IO 密集型（爬虫、文件、网络）
协程 协程（单线程内） 共享（无需锁，因为不抢占） 小 超高并发 IO（gevent）

再补一句课件的判断标准：计算操作要用 CPU 多核 → 多进程；IO 操作不需要多核 → 多线程/协程。

十一、踩坑记录

现象 原因 解决
Windows 上进程疯狂创建、卡死 忘了写 if __name__ == '__main__': 进程创建代码必须放在这个判断里
子进程里 input() 报错 multiprocessing 子进程无标准输入 输入放到主进程做
六个进程买票，票只减了一张 「读—改—写」不是原子操作 加锁；判断条件补 <= 0 return
进程加的锁不生效 锁对象没传给子进程 锁作为 args 的一部分传进去
100 个线程减 100 次，结果不是 0 线程共享变量存在竞争 Lock 或 with lock
程序卡死不动 死锁（两个锁交叉获取） 换 RLock、统一加锁顺序、设超时
线程池取结果反而更慢 result() 写在提交循环里，阻塞成串行 先收集 Future，shutdown() 后统一取，或用回调
猴子补丁不生效 monkey.patch_all() 写在 import 之后 挪到文件最前面

小结

把这一课串起来看，其实只有一条主线：并发要解决的是「等待」和「共享」两件事。

  • 等待：IO 时别傻等 → 多线程（等 IO 时释放 GIL）→ 协程（单线程内切换）
  • 共享：多线程共享进程资源 → 必须加锁；多进程不共享 → 用队列通信
  • 计算：想吃满多核 → 只能多进程（GIL 挡着）
