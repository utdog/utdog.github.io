爬虫解析与存储：BeautifulSoup、JSON 与持久化

前言

上一篇用正则把数据从字符串里"抠"出来——能用，但脆。网页结构稍微改一下，正则就全废了。

这一篇解决爬虫四步的后两步：

  • 解析提取：BeautifulSoup（按 DOM 结构找）、json 模块与 JsonPath（解析接口返回的 JSON）；
  • 保存数据：文件、CSV、JSON、MySQL。

说明：本文依据课件《3.爬虫中的初级技能》三份笔记（《1.爬虫框架Beautiful Soup详解》《2.json模块与Jsonpath》《3.爬虫的持久化储存》）整理。文中的"补充"标记部分（解析器选择、newline='' 的原因、编码处理等）是我自己加的。

一、三种抓取工具怎么选

抓取工具 速度 使用难度 安装难度
正则 最快 困难 无（内置）
BeautifulSoup 慢 最简单 简单
lxml 快 简单 一般

选型逻辑很直接：结构稳定的简单页面用正则，正式项目用 lxml 或 BeautifulSoup。

BeautifulSoup 慢在哪？课件说得很明白：

lxml 只会局部遍历，而 BeautifulSoup 是基于 HTML DOM 的，会载入整个文档，解析整个 DOM 树，因此时间和内存开销都会大很多。

但它的优点是"API 非常人性化"——支持 CSS 选择器、支持 Python 标准库的 HTML 解析器、也支持 lxml 的 XML 解析器。写起来最舒服，这也是教学都用它的原因。

版本提醒：Beautiful Soup 3 已经停止开发，现在的项目一律用 Beautiful Soup 4，装的时候包名是 beautifulsoup4，导入的是 bs4：

官方中文文档：https://beautifulsoup.readthedocs.io/zh_CN/v4.4.0/

六、JSON 与 json 模块

JSON 是什么

JSON（JavaScript Object Notation）是一种轻量级的数据交换格式，方便人阅读和编写，也方便机器解析和生成，适用于数据交互场景（比如网站前台与后台之间的数据交互）。

它的结构只有两种，正好对应 Python 的两种类型：

  • 对象：{ } 括起来的键值对，取值方式是 对象.key，值可以是数字、字符串、数组、对象；
  • 数组：[ ] 括起来，用索引取值。

调试接口时，把返回内容粘到 http://www.json.cn/ 这类在线格式化网站看一眼，比在终端里数括号快得多。爬虫抓到的 Ajax 数据，绝大多数就是 JSON。

四个函数：loads / dumps / dump / load

1）json.loads()：把 json 格式的字符串转成 Python 数据类型。

（课件注释说"json 数据自动按 Unicode 存储"——中文变成了 \u5317 这种形式，这是 Python 2 的显示方式，而且不影响取值，data['city'] 照样是"北京"。）

2）json.dumps()：把 Python 类型转成 json 字符串。

3）json.dump()：把 Python 数据类型写进文件——“让你把抓取的数据保存为 json 文件时使用”。

4）json.load()：把 json 文件读出来转成 Python 类型。

记忆法：带 s 的是 string（字符串），不带 s 的对应文件对象。loads/dumps 处理字符串，load/dump 处理文件。这个记忆法是我总结的，但特别好用。

JsonPath（了解）

JsonPath 是一种信息抽取类库，从 JSON 文档中抽取指定信息的工具，提供多种语言实现（Javascript、Python、PHP、Java）。JsonPath 对于 JSON 来说，相当于 XPath 对于 XML。

安装：从 https://pypi.python.org/pypi/jsonpath 下载后 python setup.py install（现在也可以直接 pip install jsonpath）。

JsonPath 与 XPath 语法对照：

XPath JSONPath 描述
/ $ 根节点
. @ 现行节点
/ . 或 [] 取子节点
.. n/a 取父节点（JsonPath 未支持）
// .. 不管位置，选择所有符合条件的
* * 匹配所有元素节点
@ n/a 按属性访问（JSON 是 key-value 递归结构，不需要）
[] [] 迭代器（可做数组下标、按内容选值）
| [,] 支持迭代器中做多选
[] ?() 支持过滤操作
n/a () 支持表达式计算
() n/a 分组（JsonPath 不支持）

七、持久化存储

爬虫抓完数据总得放起来，课件列了六种去处：txt 文件、csv 文件、json 文件、MySQL、MongoDB、Redis。这一节讲前四种。

1）写入文件：open 方法

参数 说明
file 文件路径，要带文件名和后缀（c:\1.txt）
mode 打开方式
buffering 缓冲大小：0 不缓冲，1 寄存行，大于 1 是缓冲区大小，负值用系统默认
encoding 编码格式（utf-8、GBK 等）

常用打开方式：

模式 含义
r 只读，指针在文件开头

r+ 读写，指针在开头
w+ 读写，存在则覆盖
a+ 读写，指针在末尾

记忆方法（课件原话）：记住 r 读、w 写、a 追加，每个模式后面加 + 就变成可读写。

这里要说一句课件的做法是对的：它用的是 %s 占位符 + 列表补位，而不是用 .format() 拼 SQL。拼接 SQL 会有注入风险（抓来的数据里如果带引号，轻则报错、重则被注入）。爬虫的数据全部来自不可信的外部网页，参数化不是可选项。

另外，正式代码的连接要用 try/finally 包起来，保证异常时也能关掉 cursor 和 conn——爬虫跑批量任务时，连接泄漏很快就会把数据库连接数占满。

八、踩坑表

现象 原因 解法
bs4 提示"没有指定解析器" 未显式传 parser BeautifulSoup(html, 'lxml')
同一份 HTML 换台机器解析结果不同 用的解析器不一样 显式指定并写进 requirements
.string 拿到奇怪的内容 该节点是注释（Comment） 解析前去掉注释，或判断类型
find_all 找不到元素 用了 tag 语法但它是第一个匹配；或属性加了空格 属性和标签之间不能有空格
中文存进 json 变成 \u5317\u4eac 没写 ensure_ascii=False json.dump(..., ensure_ascii=False)
json.load 报 Extra data 用 'a' 追加模式写成了多段 JSON 用 'w' 一次写完整份
CSV 每行之间多一个空行 Windows 文本模式的换行翻译 open(..., newline='')
CSV 用 Excel 打开中文乱码 缺 BOM encoding='utf-8-sig'
插入数据库不生效 忘了 conn.commit() 写操作后必须提交
建表报错 charset='utf-8' 写 charset='utf8'
数据里有引号导致报错/注入 用 .format() 拼 SQL 用 %s 参数化
批量插入很慢 循环 execute 用 executemany

小结

  1. 解析三件套按场景选：结构简单用正则、要按结构与 CSS 选择器找用 BeautifulSoup、追求性能用 lxml；
  2. BeautifulSoup 的四个对象（Tag / NavigableString / BeautifulSoup / Comment）和 两套 API（find_all / select）是全部核心；
  3. 接口返回的是 JSON 就用 json.loads 直接转字典，再用 JsonPath 的 $..key 把深层字段捞出来，不要用正则去啃 JSON；
  4. 落地四选一：txt 看数据、CSV 给 Excel、JSON 给程序、MySQL 给长期存储——写 MySQL 记住 %s 参数化 + commit() + finally close()。

下一篇进入"进阶技能"：XPath 语法与 lxml，以及 Fiddler 抓包——用更精确的路径表达式对付那些没有漂亮 class 和 id 的页面。
