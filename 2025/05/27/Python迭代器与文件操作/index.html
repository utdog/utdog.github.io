前言

课件在 day-13 里特意提醒：迭代器和生成器主要了解原理，目前暂时用不上，代码实现眼熟一下就行。这一天的内容是函数的收尾，另外把「文件操作」正式讲了一遍——前面读写文件一直是顺手在用，这里补上完整的模式与坑。

一、什么叫迭代

一堆数据，对它们做有规律的操作（输出、增加、修改），就叫迭代。两个前提：

  1. 需要有多个数据；
  2. 数据之间存在联系。

Python 版本从 3.6 到 3.7、3.8、3.10 也叫「迭代」，意思是一样的——一批有关联的东西逐个往前走。

二、可迭代对象与迭代器

判断是不是可迭代对象：看它有没有内置的 __iter__ 方法（能用句号点出来的东西就叫内置）。

三、生成器：自己定规则的迭代器

生成器本质上是一个自定义的迭代器：自己指定一个规则，然后按规则生成想要的数据。比如要 100 个有规律的数据，手动创建很麻烦，用生成器就一行。

生成器函数与 yield

表现形式：一个函数里有 yield 关键字。

yield 的作用和 return 类似，但有个关键差别：函数遇到 yield 是暂停，不是结束——下次 next() 会从暂停的地方继续往下跑。这也是「懒得一次算完」的实现方式：要一个算一个。

四、文件操作：三要素

「把大象放进冰箱分几步」——打开冰箱、放进大象、关上冰箱。文件操作也是三要素：

  1. 打开文件 open
  2. 操作文件（读/写）
  3. 关闭文件 close

操作模式与数据类型

模式 含义 已有文件时的行为
r read 读取 文件不存在会报错
w write 写入 原内容被覆盖，文件不存在则新建
a append 追加 在原内容后面追加，不覆盖
类型 含义
t text 文本数据，默认就是它
b byte 以字节码方式操作（图片、音频、网络编程与爬虫里会用到）

组合起来就是 wb（按字节写）、wt（按文本写，一般直接写 w 就行）、rb（按字节读）。

八、踩坑表

坑 现象 正确做法
用 w 打开已有文件 原内容被清空 只想追加就用 a
用 w 模式调用 read() io.UnsupportedOperation: not readable 读写模式要匹配
文本文件用 rb 打开后直接当字符串处理 得到 b'\xe5...' 字节串 按 b 打开就按字节处理，或改用 r + encoding
打开文件不关 文件被占用、内存泄漏 用 with open(...) as f:
忘了写 encoding='utf-8' Windows 默认 GBK，中文乱码 文本模式养成写 encoding 的习惯
把 int 当可迭代对象 TypeError: 'int' object is not iterable 只有 str/list/tuple/set/dict 等可迭代
迭代器取完还继续 next StopIteration 用 for 遍历，或先判断
生成器函数调用了却没执行 函数体根本没跑 生成器函数要用 next() 或 for 驱动
以为 list 推导式和生成器表达式一样 前者一次性生成全部，后者按需生成 数据量大时用生成器省内存
