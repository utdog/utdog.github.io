二、定义与调用

函数的使用分两步：定义（define → def） 和 调用。

语法细节：函数名的命名规则和变量一样；函数体靠缩进（一般一个 Tab = 4 个空格）划分。函数必须先定义后调用——程序是从上往下执行的。

三、参数：一个萝卜一个坑

参数分两种：

名称 出现位置 含义
形参 定义时 没有具体数据，先占个位置
实参 调用时 有具体数据，运行时取代形参

课件把函数比作锅、参数比作食材：锅一样，放什么进去就做出什么。参数一共四种：

1. 必备参数

有几个形参就得传几个实参，不多不少，否则报错。

2. 默认参数

定义时就给好默认值，调用时可以不传。默认参数必须写在右边，不能写在左边。

3. 不定长参数 *args

不确定要传几个值时使用，接收到的数据是元组。

4. 不定长参数 **kwargs

一次接收多组「键值对」，得到的是字典。

五、文档字符串与断点调试

文档字符串

写在函数体内的三引号注释，但它可以被输出，所以比普通注释更好用。它一般表达三件事：函数的作用、参数的作用、返回值的作用。

断点调试

程序默认一口气跑完，我们只看得到结果、看不到过程。断点就是设一个起点，让程序一步一步执行，能实时看到每一步的数据。PyCharm 里的用法：在行号右边点一下出现红点 → 右键 Debug → F7 单步下一步。拿到别人写的不熟悉的代码时，靠它比干读快得多。

七、名称空间与作用域

名称空间是「存放名字的地方」：变量名、函数名、模块名放在里面，对应的值（数据、代码）放在另一块内存里。一共三层：

名称空间 存放对象 加载顺序 生命周期
内建 print、input、type、sum 等内置函数 最先加载 程序启动产生，程序关闭回收
全局 写在最外层的变量名、函数名、形参 第二个加载 程序启动产生，程序关闭回收
局部 函数体内定义的变量名、函数名、形参 调用时才加载 函数调用产生，调用结束关闭

作用域是一个数据能被使用的范围。课件里的比喻很好记：全局作用域像商场公用 WiFi，谁都能用；局部作用域像家里的 WiFi，只有有密码的（函数内部）能用。

补充：Python 查找一个名字的顺序是 LEGB——Local（局部）→ Enclosing（嵌套的外层函数）→ Global（全局）→ Built-in（内建）。课件只讲了全局/局部两层，LEGB 是把它补全的说法。

八、global 提权与 nonlocal 降权

global：把局部提权为全局，让「家里的 WiFi」共享出去。

nonlocal：把嵌套函数里的外层变量「抢过来」私有化，作用于嵌套函数的外部变量。

注意：如果没有 nonlocal a，fun2 里的 a = 666 会新建一个 fun2 自己的局部变量，外层的 a 依然是 520。

九、匿名函数 lambda

给「懒人」准备的：写好功能但不想给它取名时用。

匿名函数不写 return，冒号后面那个表达式的结果就是返回值。

闭包要解决的就是这个问题——间接修改数据，保护私有数据不被轻易改变。它必须同时满足三个条件：

  1. 必须是一个嵌套函数；
  2. 外层函数必须返回内层函数；
  3. 内层函数必须操作外层函数的数据。
flowchart LR
    A["a = fun1()"] --> B["带回内层函数 fun2"]
    B --> C["a() 调用一次
food: 0 → 1"]
    C --> D["a() 再调用
food: 1 → 2"]
    D --> E["外部 food = 0
包内的 food 不受影响"]
    E --> F["a() 仍继续
food: 2 → 3"]

内层函数每次都「记得」上次的数——这就是闭包的效果：在函数被多次调用的过程中，让这些私有变量保持持久性。

十一、装饰器：不改源码给函数加功能

课件的引入是「开放封闭」原则：功能可以加（开放），源码不能改（封闭）。写好并测试过的代码不应该再被随意改动，否则出了 bug 很难修。所以给函数加功能要用「间接」的方式。

生活化类比：直接改源码 = 整容，动刀；装饰器 = 化妆，不动原样。典型场景就是京东的账单、客服、购物车——每个功能前面都要判断「是否登录」，总不能每个函数里都抄一遍。

这个函数就是一个装饰器，五步理解：

  1. login 是工具函数，作用是给别的函数加功能；
  2. 要加功能就得先接住函数，形参 f 就是被装饰的函数；
  3. 先调用 f()，保证原来的功能正常；
  4. 再写要新增的功能；
  5. 返回内层函数（原功能 + 新功能）。

两种使用方式：

flowchart TD
    A["@is_login 装饰 bill"] --> B["等价于 bill = is_login(bill)"]
    B --> C["调用 bill()"]
    C --> D["进入内层 login()"]
    D --> E["先执行原函数 f()"]
    E --> F["再执行新增功能"]

补充（课件未涉及）：真实项目里的装饰器还要处理三件事，课件这版是「最简版」，直接拿去用会踩坑。

一是被装饰函数带参数：内层函数要写成 def wrapper(*args, **kwargs)，再原样转给 f(*args, **kwargs)；
二是保留原函数的元信息：不加 functools.wraps 的话，bill.__name__ 会变成 login；
三是装饰器自己带参数：需要再套一层，变成「三层函数」。

什么情况下该用装饰器

一个功能可能会在很多函数里都用到（登录校验、计时、日志、缓存、重试），就把它写成装饰器。它的特性是：在不修改源码和调用方式的前提下给函数添加功能，而且一个装饰器能给多个函数用。

十二、踩坑表

坑 现象 正确做法
默认参数写在左边 语法错误 有默认值的参数必须放右边
形参实参数量不一致 TypeError: missing 1 required positional argument 一个萝卜一个坑，数量对齐
*args 放在 **kwargs 后面 语法错误 *args 必须在前
以为 print 能替代 return 结果拿不到，只能看 要接着用就 return
return 后面还写代码 永远不执行 想执行的逻辑放到 return 之前
在函数里直接改全局变量 报 UnboundLocalError 先 global 变量名
nonlocal 用在没有嵌套关系的地方 SyntaxError: no binding for nonlocal nonlocal 只能指向外层函数变量
混淆 f 和 f() 拿到的是函数对象 / 返回值 传函数用 f，传结果用 f()
装饰器里忘了 return f(...) 被装饰函数的返回值变成了 None 内层必须把 f(*args, **kwargs) 的结果返回
装饰器只写 def wrapper() 被装饰函数一带参数就报错 用 *args, **kwargs 兜住（补充）

十三、课件自测与小结

基础班这套笔记里的练习我挑了几道典型的（答案附在后面，建议先自己写）：

一句话串起来这篇文章：函数是装代码的容器（可以被引用、放进容器、当参数、当返回值）→ 容器里的名字按名称空间分层存放、按作用域决定谁能用（global 提权、nonlocal 降权）→ 内层函数记住外层数据就成了闭包 → 把闭包套在别的函数外面、不改源码给它加功能，就是装饰器。
