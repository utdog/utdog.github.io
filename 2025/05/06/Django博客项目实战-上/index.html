Django 博客项目实战（上）：建项目、设计模型与首页

前言

Django 班的收官项目是一个完整的个人技术博客 single_blog：文章发布、分类标签、评论点赞、登录注册、富文本编辑、全文检索，最后还要部署到 Linux 服务器。这是课程里第一个「能拿出去给人看」的东西。

我把整个过程分上下两篇记录。上篇是地基：环境与项目搭建、模型设计、Admin 后台、模板继承、首页与详情页；下篇讲扩展：登录注册、评论点赞、富文本与缩略图、haystack 全文检索。

课程用的是 Django 1.8.2，代码里还是 url() 的写法。我在需要的地方补了新版（Django 4/5）的对照写法，方便现在回看。

一、项目概览

维度 选择
框架 Django 1.8.2（课程环境：conda + Python 3.6）
数据库 SQLite3（开发阶段）
前端模板 课程提供的 Bootstrap 个人技术博客响应式模板

功能划分成两个应用：

  • myblog：文章、标签、评论、每日一句、热门排行、详情页
  • login：自定义用户的注册、登录、注销（不用 Django 自带的 auth）

三、模型设计：四张表说清一个博客

先想清楚数据关系，再写代码：

erDiagram
    User ||--o{ Post : "作者"
    Post ||--o{ Comment : "拥有评论"
    Post }o--o{ Tag : "标签"
  • User：直接用 Django Admin 里的用户表（django.contrib.auth.models.User）
  • Post：文章主体，外键关联作者，多对多关联标签
  • Comment：评论，外键关联文章
  • Tag：标签
  • Sentence：每日一句，独立小表

几个设计要点：

  1. ForeignKey 与 ManyToManyField 的选择：一篇文章只有一个作者 → 外键；一篇文章可以有多个标签、一个标签可以属于多篇文章 → 多对多。
  2. auto_now_add 与 auto_now：前者只在创建时写入，后者每次 save() 都更新，正好对应「发布时间」与「修改时间」。
  3. choices 做分类：数据库里存的是字符串本身，但 Admin 里会渲染成下拉框，比自由输入可控。
  4. verbose_name_plural：让后台显示「文章」而不是「Posts」，纯中文站点的细节。
  5. short_description：给自定义方法列起表头名（author_、tag），Admin 列表页就能显示作者名和标签串。

这段代码的价值在于四点：

  • list_display 决定列表页显示哪些列（包括自定义方法列）；
  • fieldsets 把编辑页分组，几十个字段才不会挤成一团；

  • readonly_fields 把 thumb 设为只读，因为它由代码自动生成，不该手填。

七、详情页：上下篇与相关推荐

详情页除了正文，还有两个提升体验的小功能：上一篇 / 下一篇，以及按标签相关推荐。

三个值得记住的点：

  1. tag.post_set.all()：多对多/外键的反向查询，从一个标签对象拿到它关联的所有文章（也可以用 related_name 自定义名字）；
  2. 去重：一篇文章命中多个相同标签会被取到多次，用 set() 去重（顺便注意 QuerySet 元素可哈希）；
  3. get_object_or_404：url 参数被乱改时直接返回 404，比抛 DoesNotExist 友好。

小结

上篇走完了「项目骨架 → 数据模型 → 后台 → 模板 → 首页/详情页」这条主线，其中最有价值的三件事是：先把表关系画清楚再写模型、Admin 用 fieldsets + 跨关系 search_fields 变成可用后台、分页要记住 Page 对象与 QuerySet 的区别。

下篇接着写扩展部分：自定义用户的注册登录（session + sha1）、评论与点赞（AJAX + 按天限流）、富文本与自动缩略图、haystack + whoosh 中文全文检索，以及最后用 nginx + uwsgi 部署到 Linux。
