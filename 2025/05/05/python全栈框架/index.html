python全栈框架

前言

学完语法之后，我一直想知道“一个网站到底是怎么跑起来的”。这篇笔记记录我用 Django 搭第一个 Web 应用的完整过程：从项目结构、路由、模型、视图、模板这条主线走一遍，再补上后台管理、表单校验、用户认证和部署要点。文中拿一个“课程笔记管理”小项目当例子，表结构沿用前面 MySQL 那篇。

一、一次请求发生了什么

graph LR
    A[浏览器] -->|HTTP 请求| B[URLconf 路由]
    B --> C[View 视图]
    C --> D[Model 模型 / ORM]
    D --> E[(数据库)]
    C --> F[Template 模板]
    F -->|HTTP 响应| A

Django 把这个模式叫 MTV：Model（数据）、Template（展示）、View（逻辑）。它和 MVC 的区别只是“C 由框架自己当了”——路由分发那部分是 Django 替你做的。

二、Django 还是 Flask

维度 Django Flask
定位 大而全的框架 微框架，按需拼装
自带 ORM 有 无（SQLAlchemy 等自选）
后台管理 自带 Admin 需要自己写或装扩展
用户认证 自带 需要 Flask-Login 等
上手速度 慢一点，但省心 很快，但选型要自己拿主意
适合 内容型站点、管理系统 小型 API、微服务

结论：要做完整的业务系统选 Django，只写一个接口服务选 Flask。

三、环境与项目结构

一个项目可以包含多个应用，应用之间不要互相 import 模型，需要共用就抽成第三个应用。

七、模板层

三个高频过滤器：truncatechars（截断）、date（格式化时间）、safe（不转义，慎用）。变量默认是转义的，这是防 XSS 的第一道防线，不要随手加 |safe。

八、Admin 后台

几十行代码换来一个能搜索、筛选、分页的运营后台，这是 Django 最划算的部分。

九、表单与校验

视图里 form.is_valid() 之后用 form.save() 落库，模板里 {{ form.as_p }} 就能渲染，错误信息自动带出来。校验永远放在服务端，前端的限制只是体验优化。

十、用户认证

Django 自带的 Session 认证 + @login_required 已经覆盖大部分场景；要按角色控权就用 @permission_required 或自定义装饰器。密码在数据库里是 PBKDF2 哈希，别自己造轮子。

十一、静态文件与媒体文件

  • STATIC_URL/STATICFILES_DIRS：CSS、JS、图片这类开发时就有的文件，部署前 python manage.py collectstatic 汇总。
  • MEDIA_URL/MEDIA_ROOT：用户上传的文件，需要单独配 Nginx 或对象存储。
  • 生产环境 DEBUG = False 时 Django 不再帮你发静态文件，一定要交给 Nginx。

十二、部署要点

链路是 Nginx（静态文件 + 反向代理）→ Gunicorn（跑 WSGI 应用）→ Django。别忘了 python manage.py check --deploy，它会告诉你哪些安全项没配。

十三、踩坑记录

报错 原因 解决
no such table: notes_note 改完模型没迁移 makemigrations + migrate
TemplateDoesNotExist 模板目录没登记 settings.TEMPLATES 里加 DIRS，或放对应用目录下
CSRF verification failed 表单少了 CSRF token 表单里加 {% csrf_token %}
Specifying a namespace without app_name include 时带了 namespace 在应用 urls.py 里写 app_name = "notes"
django.db.utils.OperationalError: (2002) 数据库连不上 检查服务是否启动、端口和账号密码
静态文件 404（生产） DEBUG=False 且没配 Nginx collectstatic + Nginx 指向 STATIC_ROOT

小结

Django 的学习曲线主要卡在两处：一是 MTV 的分工，二是 ORM 的惰性求值。把“路由 → 视图 → 模型 → 模板”这条线走通一遍，剩下的都是查文档。下一步我打算把这个笔记项目加上分类筛选和全文搜索，再试着用 Docker 部署一次。
