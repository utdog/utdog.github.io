Git 与 Gitee：从单人版本控制到多人协作

前言

在学 Git 之前，我的「版本管理」方式是给文件夹改名：项目、项目-改、项目-最终、项目-最终2。课程里第一次用 Git 管项目时，最直观的冲击是代码有了可回退的历史；而多人协作那一课则让我明白，Git 真正解决的问题是**「几个人同时改同一个项目，怎么不互相覆盖」**。

课件用的是码云（Gitee）：GitHub 服务器在国外，国内访问经常抽风，而 Gitee 速度快、免费、私有库不限额。命令本身和 GitHub 完全一样，换个远程地址即可。

协同开发时用户名不能重复，否则提交记录分不清谁是谁。

二、三个区：先把「代码放在哪」想清楚

这是 Git 最核心的概念，课件用一张图讲透了：

graph LR
    A[工作区
你写代码的地方] -->|git add| B[暂存区
准备提交的内容]
    B -->|git commit| C[仓库区
一个版本的历史]
    C -->|git push| D[远程仓库
Gitee]
    D -->|git pull| A
  • 工作区：你实际编辑文件的地方，增删改都发生在这里；
  • 暂存区：介于工作区和仓库区之间，git add 把改动放进来；
  • 仓库区：git commit 后形成一条永久记录，可查看、可回退；
  • 远程仓库：push 送上去、pull 拉下来（就是 Gitee 上的那个仓库）。

对应命令：

git checkout -- 文件 这个命令很实用：不小心把某段代码删了、又还没提交，用它就能恢复——前提是那段代码已经 add 过。

三、远程仓库：建仓 + SSH 公钥

1. 在 Gitee 上创建项目

登录 gitee.com → 概览 → 创建项目。注意公有库和私有库都不限数量，练习项目直接建私有库更省心。

2. 配置 SSH 公钥

要让本机能和 Gitee 通信，得先把自己机器的公钥交给 Gitee：

执行后会问三件事：保存路径（留空默认 ~/.ssh）、密码（可留空，填了以后每次操作都要输）、确认密码。

把复制的公钥粘到 Gitee 的「设置 → SSH 公钥」里即可。私钥 id_rsa 绝不能外传，公钥可以随便给。

3. 克隆项目

第一次连接会提示是否信任主机，输入 yes。克隆下来的目录自带完整的 Git 历史，不需要再 init。

四、分支策略：三条线各司其职

课件给的协作规范非常清晰，项目里公用分支 + 个人分支：

分支 作用
master 用于发布，默认分支。dev 测试没问题后才合并进来
dev 开发阶段的整合分支，每个人阶段性代码都往这里合
个人分支（如 it、agou） 每个人自己的开发分支，互相不干扰

整体流程是：开发之初建好仓库 → 组员克隆框架、同步分支、各自开发 → 需要发布时把各分支合并到 dev，再合并到 master。

六、合并与冲突：不慌，手动改就行

当项目功能开发完成，就要合并到 dev：

push 被拒绝怎么办

多人改同一个文件时，你 push 会遇到：

这不是「代码错了」，而是有人比你先进了同一个文件。按照提示做：

看懂冲突标记

pull 之后 Git 会在冲突文件里插入三行标记：

处理步骤：

  1. 打开冲突文件，手动决定保留哪段（两段都需要就都留下）；
  2. 删掉 <<<<<<<、=======、>>>>>>> 这三行标记；
  3. 如果拿不准别人那段代码该不该保留，直接找写这段代码的同事确认（课件原话：不能确定是否保留，可以与编写该语句的人员沟通）；
  4. 改完保存，再 add → commit → push，冲突就解决了。

口诀：冲突不是错误，只是 Git 不知道你想留哪一版；决定权永远在人手里。

七、历史、回退与发布

版本号的说法要记住：

写法 含义
HEAD 当前版本（最新提交）
HEAD^ 上一个版本
HEAD^^ 或 HEAD~2 上两个版本
一串哈希（如 8f81b29） 指定的某次提交

git diff 的输出里 + 表示工作区比仓库区多出来的内容，- 表示少掉的内容。

发布：dev → master → 打标签

所有组员都合并到 dev、测试没问题之后，就可以发布：

打标签的意义：将来线上出问题，能快速定位「当时发布的是哪一版代码」。

八、踩坑记录

现象 原因 解决
Please tell me who you are 没配 user.name / user.email git config --global 补上
push 提示更新被拒绝 远程有别人新提交 git pull 合并冲突后再 push
git push 不知道怎么推哪个分支 本地分支没跟踪远程分支 git branch --set-upstream-to=origin/分支 分支
代码删掉想恢复 工作区被改坏 若已 add 过，用 git checkout -- 文件
回退后代码「不见了」 git reset 只回到暂存区 再 git checkout -- 文件 恢复到工作区
ssh-keygen 后连不上 公钥没配到 Gitee，或有旧密钥 删旧 ~/.ssh 重新生成并粘贴公钥
第一次 clone 卡住 提示是否信任主机没回答 输入 yes
分支删错了 git checkout -d 不可恢复 用 git reflog 找提交号抢救

小结

Git 的知识点看着多，其实可以压缩成四句话：

  1. 三个区：改在工作区，add 到暂存区，commit 进仓库区，push 上服务器；
  2. 分支各司其职：个人分支开发 → dev 集成 → master 发布；
  3. 冲突不可怕：pull → 手动改 <<<<<<< 之间的内容 → add/commit/push；
  4. 历史能回退：reflog 是最后的安全网。

顺带一提，本博客也用 Git 管理（源码在本地仓库、生成结果推送到 GitHub Pages），但流程和课件完全不同：Hexo 是静态站点，hexo generate 出来的 public/ 全量推送到 Pages 仓库，不需要分支策略；而课件这套 master/dev/个人分支的玩法，是为「多人协作写同一个应用」准备的。

说明：本文依据课件《09-git和码云》整理，命令与流程均来自课件；其中「reflog 抢救误删分支」「markdown 化的工作区/暂存区流程图」是我补充的说明。
