Django 博客项目实战（下）：登录注册、评论点赞、缩略图与全文检索

前言

上篇把博客的骨架搭好了：模型、后台、模板、首页与详情页。这篇写四块「让站点活起来」的扩展——自建用户系统、评论与点赞、富文本与自动缩略图、中文全文检索。其中 haystack 那部分的坑最多，网上大部分教程都没讲清中文分词要改源码这件事。

一、自建用户系统：不用 auth 也能做

课程里没有直接用 Django 自带的 auth，而是新建了一个 login 应用、自己建用户表。理由很实际：自带 User 表字段固定（username/email/password…），想加「是否注销」「注册时间」这类业务字段就得额外建 Profile 表关联，不如自己写一张干净的表。

密码不能明文存。课程里的做法是抽一个工具函数集中处理加密：

注意：SHA-1 现在不安全（已被碰撞攻击攻破，且没有加盐，彩虹表可查）。课程用它只是入门演示，正规项目应该用 Django 自带的 make_password / check_password（内部是 PBKDF2）或 bcrypt/argon2。

注册与登录：类视图 + 一整套校验

登录视图的逻辑对称，核心是「先查用户是否存在，再比密码哈希」：

四个值得记的点：

  1. 类视图的 get/post 分派：同一条 URL，GET 返回页面、POST 处理数据，比在函数里写 if request.method == "POST" 清爽；
  2. 校验顺序：必填 → 格式 → 一致性 → 唯一性，先便宜的后昂贵的，错误信息只回一条；
  3. filter().first() 而不是 get()：避免账号不存在时抛 DoesNotExist 变成 500；
  4. set_expiry(86400)：不设的话关掉浏览器会话就失效（Django 默认），设了才是「一天内免登录」。

注册页还有一个 AJAX 小功能：输入用户名时实时提示「账号已存在」。

什么时候还是该用 Django 自带的 auth：需要权限体系（分组、权限点）、需要第三方登录、需要密码强度的持续升级时，自带 auth 是更稳的选择；它已经处理好了加盐哈希、密码重置、request.user 注入这些事。这个项目自建只是为了练手。

二、评论：视图装饰器 + JsonResponse

页面用 AJAX 提交评论，所以接口不能返回页面，要么返回 JSON、要么重定向。这里约定「先判断登录态」：

三个细节：

  • comment.post_id = commentID：外键赋值时用 post_id 直接给主键值，不用先 Post.objects.get() 查一次；
  • JsonResponse 不能直接序列化 datetime：必须 strftime 成字符串，或者用 DjangoJSONEncoder；
  • [:100] 限制条数：评论多了不能一次全返回。

CSRF 的处理有两种取舍：模板里带 csrfmiddlewaretoken（安全），或者给视图加 @csrf_exempt（方便但等于关掉这道防线）。这个课程项目为了调试方便用了后者，正式项目不要这么干——Django 的 CSRF 保护能挡住跨站伪造提交，关掉等于给攻击者开门。

三、点赞：用 session 做「每日一赞」

点赞的需求是「同一篇文章一天只能点一次」。项目没有单独建点赞记录表，而是把时间戳塞进 session：

思路是：在 session 里存「什么时候才能再点」而不是「点过没有」，判断条件就变成 当前时间 > 记录时间，逻辑更简单。

局限也很明显：session 存在浏览器 Cookie 里，清缓存、换浏览器、开无痕都能再点一次。要真正防刷得建一张 点赞记录表（用户 + 文章 + 日期，联合唯一），或者用 Redis 记 用户:文章:日期 的键。

重写 save() 生成缩略图

列表页如果直接用封面原图，一张几 MB 的图在首页加载十几次，页面会非常慢。项目在 Post.save() 里自动生成缩略图：

为什么要 save 两次：ImageField 只有在第一次 save() 之后，self.img.path 才指向真实存在的文件；拿到文件才能用 Pillow 读它、生成缩略图；缩略图存好后又得再 save() 一次才会把 thumb 字段写进数据库。这是个很典型的「依赖前一步结果」的场景，顺序不能颠倒。

小结

下篇这四块里，最值得动手的是 haystack 的中文改造——它逼着你去看第三方库的源码，理解「分词器决定召回率」这件事；最容易被忽略的是 Post.save() 的两段式写法，它体现了一个通用套路：当一步操作依赖上一步的产物时，就老老实实分两步做。而最该被替换掉的是自建用户系统：项目是为了练手，真上线应该换回 Django auth（PBKDF2 加盐）或至少换成 make_password/check_password。

到这里，博客的「内容 + 互动 + 检索」就齐了。下一步本该是部署：虚拟环境、uwsgi 拉起 Django、nginx 反代并托管静态文件、DEBUG/ALLOWED_HOSTS/SECRET_KEY 的收尾——课程对应的课件是 PDF，我还没有解析，就先不凭印象写了。
