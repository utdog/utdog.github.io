爬虫进阶：XPath 与 Fiddler 抓包

前言

上一篇的 BeautifulSoup 好用，但它有一个前提：页面得有像样的 class 和 id。

真实项目里经常遇到这种情况——一堆嵌套的 <div>，class 全是 a1b2c3 这种随机串，select 根本下不去手。这时候就该 XPath 出场了：它按"路径"定位节点，能精确到"第几个、哪个父节点下面的哪一层"。

这一篇讲两件事：

  • XPath + lxml：写更精确的定位表达式；
  • Fiddler：比浏览器控制台更强的抓包工具。

说明：本文依据课件《4.爬虫中的进阶技能》两份笔记（《1.解析神器Xpath详解》《2.爬虫中的常用工具》）整理。Fiddler 那部分课件主要是截图，我按流程转成了文字步骤。

一、XML 与 XPath

为什么先讲 XML

XPath 的全称是 XML Path Language——它本来就是为 XML 设计的。而 HTML 和 XML 长得很像，所以我们可以先把 HTML 文件转换成 XML 文档，再用 XPath 去查找节点。这就是 lxml 做的事。

什么是 XML：

  • XML 指可扩展标记语言（Extensible Markup Language）；
  • 它很类似 HTML；
  • 设计宗旨是传输数据，而不是显示数据；
  • 标签需要我们自行定义。

XML 与 HTML 的区别：

数据格式 描述 设计目标
XML Extensible Markup Language（可扩展标记语言） 被设计为传输和存储数据，焦点是数据的内容
HTML HyperText Markup Language（超文本标记语言） 显示数据以及如何更好显示数据
HTML DOM Document Object Model for HTML（文档对象模型） 通过 DOM 可以访问所有 HTML 元素及其文本和属性，也可以修改、删除、创建元素

一段 XML 长这样：

一眼就能看出来：它是一棵树，而这棵树正是 XPath 能够"按路径找"的基础。

XML 的节点关系

理解这五个词，XPath 的写法就都说得通了：

关系 含义 例子
父（Parent） 每个元素以及属性都有一个父 book 是 title、author、year、price 的父
子（Children） 元素节点可有零个、一个或多个子 title、author、year、price 都是 book 的子
同胞（Sibling） 拥有相同父的节点 title、author、year、price 互为同胞
先辈（Ancestor） 某节点的父、父的父，等等 title 的先辈是 book 和 bookstore
后代（Descendant） 某个节点的子、子的子，等等 bookstore 的后代是 book、title、author…

记住"先辈往上、后代往下"这一对，/ 和 // 的区别就不会记反。

什么是 XPath

XPath (XML Path Language) 是一门在 XML 文档中查找信息的语言，可用来在 XML 文档中对元素和属性进行遍历。

官方文档：http://www.w3school.com.cn/xpath/index.asp

开发/调试工具：

  1. XMLQuire：开源的 XPath 表达式编辑工具（XML 格式文件可用）；
  2. XPath Helper：Chrome 插件（最常用的一个，能在页面上实时验证表达式）；
  3. XPath Checker：Firefox 插件。

二、XPath 语法

XPath 用路径表达式来选取节点，写法"和我们在常规的电脑文件系统中看到的表达式非常相似"。

最常用的六个表达式

表达式 描述
nodename 选取此节点的所有子节点
/ 从根节点选取
// 从匹配选择的当前节点选择文档中的节点，而不考虑它们的位置
. 选取当前节点
.. 选取当前节点的父节点
@ 选取属性

路径表达式示例：

路径表达式 结果
bookstore 选取 bookstore 元素的所有子节点
/bookstore 选取根元素 bookstore（路径起始于 / 则始终代表绝对路径）
bookstore/book 选取属于 bookstore 的子元素的所有 book 元素
//book 选取所有 book 子元素，不管它们在文档中的位置
bookstore//book 选择属于 bookstore 后代的所有 book 元素，不管位于什么位置
//@lang 选取名为 lang 的所有属性

/ 与 // 的区别是整个 XPath 里最容易写错的地方：/ 只找直接子节点，// 找所有后代。定位不到元素时，第一个要检查的就是这里。

谓语（Predicates）

谓语用来查找某个特定的节点，或者包含某个指定值的节点，被嵌在方括号中。

路径表达式 结果
/bookstore/book[1] 选取属于 bookstore 子元素的第一个 book 元素
/bookstore/book[last()] 选取最后一个 book 元素
/bookstore/book[last()-1] 选取倒数第二个 book 元素
/bookstore/book[position()<3] 选取最前面的两个 book 元素
//title[@lang] 选取所有拥有名为 lang 的属性的 title 元素
//title[@lang='eng'] 选取所有 title 元素，且 lang 属性值为 eng
/bookstore/book[price>35.00] 选取所有 price 元素值大于 35.00 的 book 元素
/bookstore/book[price>35.00]/title 在上面的基础上再取它们的 title

注意 XPath 的索引从 1 开始（不是 0），这一点和 Python 正好相反。

通配符与多路径

通配符 描述
* 匹配任何元素节点
@* 匹配任何属性节点
node() 匹配任何类型的节点
路径表达式 结果
/bookstore/* 选取 bookstore 元素的所有子元素
//* 选取文档中的所有元素
html/node()/meta/@* 选择 html 下面任意节点下的 meta 节点的所有属性
//title[@*] 选取所有带有属性的 title 元素

用 | 选取若干路径：

路径表达式 结果
//book/title | //book/price 选取 book 元素的所有 title 和 price
//title | //price 选取文档中所有 title 和 price
/bookstore/book/title | //price 前者取 bookstore 下 book 的 title，后者取文档中所有 price

一句话总结这一节：XPath 语法内容就是这些，在 Python 抓取时要先转换为 XML。

三、lxml 库

lxml 是一个 HTML/XML 的解析器，主要功能是解析和提取 HTML/XML 数据。

它的关键优势：和正则一样是用 C 实现的，所以性能很高，同时又能用 XPath 精确、快速地定位元素。

官方文档：http://lxml.de/index.html

使用流程（三步）

也可以直接从文件解析：html = etree.parse('hello.html')，得到的是 _ElementTree 对象。

最常用的写法：先取节点列表，再逐个节点继续取

课件总结的这个套路，是所有列表页爬虫的标准骨架：

关键在那个点号：

  • r.xpath('./xxx') 里的 . 表示当前节点，所以是找"这个节点下面的 xxx"；
  • 如果写成 r.xpath('//xxx')，那就又跑回整个文档去找了，前面的基准表达式就白写了。

这是 XPath 写法里第二容易踩的坑（第一是 / 与 //）。在循环里用相对路径，一定要带上开头的 .。

四、抓包神器 Fiddler

Fiddler 是什么

Fiddler 是位于客户端和服务器端之间的代理，也是目前最常用的抓包工具之一。它能够记录客户端和服务器之间的所有请求，可以针对特定的请求分析请求数据、设置断点、调试 web 应用、修改请求的数据，甚至可以修改服务器返回的数据。

工作原理：它是以代理 web 服务器的形式工作的，使用代理地址 127.0.0.1，端口 8888。

既然本机 HTTP 通信都会经过这个代理，Fiddler 自然就能拦截到所有请求。

和浏览器 F12 的区别：F12 只能看浏览器发出去的请求，而且关掉标签页就没了；Fiddler 是系统级代理，手机 App、其他程序、甚至另一台设备的请求都能抓——所以做移动端接口分析时基本都用它。

安装与配置

下载：官网 https://www.telerik.com/download/fiddler，选好相关信息（用途、邮箱、国家）后点 Download。

安装：双击安装包 → I Agree → 选安装目录（默认即可）→ Install → Close。

配置：Tools > Options > Connections

  1. 端口默认是 8888，可以修改；
  2. 勾选 Allow remote computers to connect，然后重启 Fiddler，再次打开时会弹出一个信息，选 OK 即可（这一步是为了让别的设备能连上你的代理）；
  3. Fiddler 默认只抓 http 请求，要抓 https 请求，需要进入 Tools > Fiddler Options 打开对应的 https 解密选项（这也是"装了 Fiddler 但抓不到 https 包"的常见原因）。

抓 https 的本质是 Fiddler 用它自己的证书做中间人解密——所以它会往系统里装一张根证书。这也是为什么在公司环境里装 Fiddler 前最好确认一下合规要求。

界面面板速查

Fiddler 的每个请求都能切成很多种视图来看，知道哪个面板解决什么问题，比记住所有按钮有用。

请求（Request）部分：

面板 用途
Headers 客户端发给服务器的 HTTP 请求头，分级视图，含 Web 客户端信息、Cookie、传输状态等
Textview 把 POST 请求的 body 显示为文本
WebForms 显示请求的 GET 参数和 POST body 内容（表单类接口最常用）
HexView 用十六进制显示请求
Auth 显示响应头中的 Proxy-Authorization（代理身份验证）和 Authorization（授权）
Raw 把整个请求显示为纯文本
JSON 显示 JSON 格式文件
XML 请求 body 是 XML 时，用分级 XML 树显示

响应（Response）部分：

面板 用途
Transformer 显示响应的编码信息
Headers 分级视图显示响应头
TextView 用文本显示响应 body
SyntaxView 响应数据（语法高亮）
ImageView 请求是图片资源时，直接显示图片
HexView 十六进制显示响应
WebView 响应在 Web 浏览器中的预览效果
Auth 显示响应头中的 Proxy-Authorization 和 Authorization 信息
Caching 显示该请求的缓存信息
Privacy 显示该请求的私密（P3P）信息
Raw 把整个响应显示为纯文本
JSON 显示 JSON 格式文件
XML 响应 body 是 XML 时，用分级 XML 树显示

日常最常用的三个：Headers 抄请求头、WebForms 看 POST 参数、Raw 看原始请求体。抓不到参数时，先看 Raw——它是不会骗人的那一层。

五、踩坑表

现象 原因 解法
//li/span 取不到元素 <span> 是后代不是直接子元素 改成 //li//span
循环里每个节点都取到全部数据 用了 //xxx 绝对路径 用 ./xxx 或 .//xxx（带点号）
索引取错元素 XPath 从 1 开始 [1] 是第一个，别写 [0]
拿到元素却打印不出文本 元素是 _Element 对象 用 .text
想取属性却拿到节点 忘了 @ //li/a/@href
Fiddler 抓不到 https 默认只解 http 在 Fiddler Options 里开启 https 解密并信任证书
手机连不上 Fiddler 没允许远程连接 / 不在同一网段 勾选 Allow remote computers 并重启
拿到一堆乱码请求 没开对应面板 用 Raw / HexView 看原始内容

小结

  1. XPath 是为 XML 设计的，HTML 转成 XML 树之后就能用路径精确导航；
  2. 两个必须记住的符号规则：/ 是直接子节点、// 是所有后代；循环里用相对路径必须带 .；
  3. lxml 三步：from lxml import etree → etree.HTML(html) → .xpath('表达式')，返回的永远是列表；
  4. XPath 与 BeautifulSoup 不是二选一：日常页面用 select 更快，结构刁钻的页面用 XPath 更稳；
  5. Fiddler 是系统级代理（127.0.0.1:8888），比 F12 强在能抓非浏览器流量、能改包、能设断点——手机 App 的接口分析基本靠它。
