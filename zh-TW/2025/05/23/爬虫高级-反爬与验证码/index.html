爬虫高级：反爬机制与验证码识别

前言

爬到第五篇，顺风顺水的日子结束了。

前面四篇的代码在练习站点上都能跑通，但把同样的代码指向真实网站，很可能第一件事就是被挡回来——返回 403、返回一个空壳页面、或者干脆弹出一个验证码。

这一篇讲的就是"对方怎么防"和"我们怎么破"：

  • 反爬机制的常见类型：IP 限制、动态页面、headers 校验、参数加密、验证码；
  • 对应的应对手段：代理 IP、抓包分析、UA 池、Cookie 模拟登录；
  • 验证码识别：Tesseract OCR（含二值化与降噪）、百度 OCR、打码平台。

说明：本文依据课件《5.爬虫中的高级技能》两份笔记（《1.反爬虫介绍》《2.图片验证码》）整理。最后加了一段课件没写、但我觉得必须说的合规提醒。

一、反爬与反反爬全景

先把两边的牌摊开看。

常见的反爬机制：

  1. 通过 User-Agent 控制访问（判断请求是不是来自真实浏览器）；
  2. 通过 Referer 控制访问（判断请求是不是从站内跳过来的）；
  3. 通过 IP 限制访问——监控用户 IP，如果短时间请求次数过大，封 IP；
  4. 通过 Cookie 控制访问（要求登录态）；
  5. 登录及验证码（限制账号访问频率、登录 3 次错误就拦截）；
  6. 健全的账号体制——核心数据仅登录可见；
  7. 动态加载数据（数据由 JS 异步加载，response 里根本没有）。

反反爬策略：

手段 说明
伪造请求头 加上 UA、Referer、Cookie，把自己伪装成浏览器
代理 IP 隐藏真实 IP，避免被针对性地封
限制请求频率，模拟用户 加 time.sleep()，别用高速循环砸服务器
验证码识别 OCR / 打码平台
selenium + webdriver 直接用真实浏览器渲染页面，动态内容也能拿到

网站为什么要反爬

  1. 保护网站自身的正常运转——爬虫的高频请求会占满服务器资源；
  2. 保护数据安全——数据是网站的资产；
  3. 版权问题——数据有商业价值，不愿意被无偿批量拿走。

站在对面想一想：如果我们的脚本每秒请求 10 次、两天不带停，对方的运维一定先受不了。"反爬"首先是一个资源保护问题，其次才是技术对抗问题。 这一点决定了后面所有策略的底线：控制频率永远是第一优先级。

二、反爬机制一：IP 限制与代理 IP

什么是代理 IP

代理 IP 就是代替我们真实 IP 去访问网络的 IP。通过它访问网站，服务器看到的就是代理 IP，而不是我们的真实 IP。

为什么要用：

  1. 让服务器以为不是同一个客户端在请求（用多个 IP 分摊请求）；
  2. 防止我们的真实 IP 被封锁——封了代理换个新代理就行，不影响自己上网。

免费代理 IP 的获取网站（课件列举）：西刺代理、快代理、全网代理、代理精灵等。

重要提醒：免费代理池的可用率通常极低（大量是失效的、或者被目标站早已拉黑的），而且有些免费代理本身就会记录你发出去的明文请求。所以免费代理只适合练习，登录类请求千万不要走来源不明的代理。

代理的三类

类型 服务端能看到什么
透明代理 能看到用户的真实 IP，也知道用了代理
普通（匿名）代理 知道有人通过代理访问，但不知道真实 IP
高匿代理 既不知道真实 IP，也不能识别出你用了代理

常用代理类型的特点：

类型 可用率 速度 稳定性 价格 适用
普通代理 低 慢 不稳定 免费或便宜 学习测试
私密代理 高 较快 稳定 适中 爬虫最常用
独享代理 极高 快 极稳定 贵 对稳定性要求高的项目

用法

几个要点：

  1. proxies 字典里 http 和 https 要分别指定（协议名、IP、端口都要对）；
  2. 一定要带 timeout——代理不可用时，不带超时的请求会一直挂着；
  3. 私密代理要带账号密码，格式是 协议://用户名:密码@IP:端口：

思考题（课件留的）：如何自己建立一个代理 IP 池？
思路是三步——抓免费代理 IP 网站的列表 → 逐个测试可用性（拿 httpbin.org 试一次，有响应才算活）→ 把可用的存进文件，用的时候随机取。这正是后面要写爬虫工程的思路：把"获取资源"和"使用资源"分开。

三、反爬机制二：动态页面

静态页面与动态页面

静态页面 动态页面
数据来源 数据都在 response 里 数据不直接渲染于 response
技术特征 服务端直接返回完整 HTML AJAX 局部刷新、JS 加载、常伴随加密
典型场景 小网站、对安全性关注度不高的数据 主流网站、核心数据

如何判断一个页面是不是动态加载：

  1. 页面有"加载更多"、滚动到下面一点点就刷新出新内容；
  2. elements 里能解析到数据，但 response 里查不到——这是最直观的判据；
  3. 抓包能看到额外的 AJAX 异步请求。

response 里没有数据怎么办：控制台抓包分析

浏览器 F12 的开发工具，三处会用就够了：

面板 用途
Network（网络） 记录所有请求。下面可选 ALL（全部）/ XHR（ajax 请求）/ JS（js 文件）；点开某一项后右侧能看到 Headers / Preview / Response
Sources（源代码） 对 js 文件格式化后可以断点调试，用来搞清楚参数是怎么生成的
Console（控制台） 直接执行 js 语句，测试加密函数最方便

右侧详情面板三个页签：

  • Headers：General（请求地址、方法、状态码）、Response Headers（响应头）、Request Headers（请求头）、Query String Parameters（GET 参数）、Form Data（POST 参数）；
  • Preview：格式化后的响应（JSON 会折叠成树）；
  • Response：原始响应文本。

实操顺序：先 Network 里 Clear 清空 → 在页面上做一次目标操作（翻页、点"加载更多"）→ 看新冒出来的请求。那个新请求，就是要找的接口。

AJAX 与 JSON

  • AJAX（Asynchronous JavaScript And XML）：一种用于创建快速动态网页的技术，通过在后台与服务器进行少量数据交换，实现网页的异步更新。这意味着可以在不重新加载整个网页的情况下，对网页的某部分进行更新。传统上用的是 XML，现在基本都用 JSON。
  • JSON（JavaScript Object Notation）：一种轻量级的数据交换格式，是 JS 对象的字符串表示法，用文本表示一个 JS 对象的信息，本质是一个字符串。

动态页面数据加载的特征：

  1. 几乎统一是 JSON 字符串；
  2. 几乎都伴随鼠标、键盘事件（滚动、点击才触发）；
  3. 几乎无法直接在 html 的 response 中看到目标数据。

动态页面抓取固定套路（六步）

这是本节最该背下来的部分：

  1. 请求目标 url；
  2. F12 的 Network 面板里过滤 XHR / JS；
  3. 在网页上操作（翻页、下拉、点击）；
  4. 查看新增的请求项；
  5. 分析该请求的参数及规律；
  6. 确定目标数据的 url / 接口 → 发请求拿到 response → 解析（多数是 JSON） → 持久化存储。

一句话：静态页爬"页面"，动态页爬"接口"。只要能找到接口，动态页面反而比静态页面更好爬——因为它给的是干净的 JSON，不需要再解析 HTML。

四、反爬机制三：headers 校验

User-Agent

反爬原理：浏览器发请求会带自己的 UA；而爬虫默认没有 UA，用的是模块的默认设置（比如 python-requests/2.25.1）——一眼就能看出来不是浏览器。

Referer

反爬原理：爬虫默认是不带 referer 的，服务器靠这个判断请求是不是从自家页面点过来的。

应对：在 headers 里加上目标站的地址，例如 'Referer': 'https://www.example.com/'。

Cookie

反爬原理：有些数据必须登录才能看（会话机制靠 Cookie 维持）。

Cookie 和 Session 的关系（上一篇讲过，这里再对齐一次）：Cookie 存在客户端，Session 存在服务器；服务器通过 Cookie 里的 sessionid 认出"你是谁"。

应对：模拟登录的三种方法：

方法 做法 适用
方法一 手动登录一次，把浏览器里的 Cookie 复制到 headers 里 最快，适合临时调试；Cookie 会过期
方法二 requests.get(url, cookies=cookies)，把 Cookie 处理成字典传进去 需要程序里灵活切换 Cookie
方法三 session = requests.session()：先用 session.post 登录，session 会自动保存 Cookie，之后再 get 就是登录态 工程里最推荐，还能复用连接

注意：登录接口通常还有隐藏参数（csrf token、时间戳、签名），必须先在登录页的 html 里把这些值抓出来，再一起 post 过去——这就是下面"请求参数反爬"的内容。

五、其他反爬手段

手段 原理 应对
请求参数被隐藏/加密 登录数据可能来自 html 里的静态隐藏域、或由 js 生成 先从 html 提取；js 生成的用 js2py 执行，或直接用 selenium
验证码 强制人机识别 打码平台 / 机器学习 / 手动输入一次
CSS 反爬 用 CSS 位移（background-position）把真实数字/文字挪出来，源码里是乱序的 计算偏移量，把正确的内容"拼"回来
JS 动态生成数据 关键数据由前端 js 运行时生成 解析关键 js 逻辑，用 Python 复现
编码格式反爬 响应内容是特殊格式编码 按对应格式解码

总结一下"常见反爬机制与处理方式"：

  1. headers 反爬（User-Agent / Referer / Cookie）→ 伪造请求头、维护 UA 池、session 模拟登录；
  2. IP 限制→ 代理 IP / 控制请求频率；
  3. 动态页面→ 抓 XHR 接口；
  4. 参数加密→ 读 js、用 js2py / selenium；
  5. 验证码→ OCR 或打码平台。

六、图片验证码与 OCR

为什么会有验证码

加载验证码的方式：<img> 元素加载验证码时，需要携带 Cookie；输入框则作为表单数据的一部分提交。

CAPTCHA：全称 Completely Automated Public Turing test to tell Computers and Humans Apart（全自动区分计算机和人类的图灵测试）。

作用：防止恶意破解密码、刷票、论坛灌水、刷页。

使用场景：注册、登录，以及频繁请求时弹出验证。

处理方案三种：

方案 特点 适用
手动输入 只能在一次登录中使用，一次登录后 Cookie 可以持续使用一段时间 要求不高的小项目，最省事
图像识别引擎 用 OCR 自动识别 验证码样式简单、固定的站点
打码平台 把图片发给平台、由人/模型识别后返回结果，爬虫中常用 复杂验证码、批量场景

"手动输入一次 + Cookie 持续使用"是很实用的一招：很多网站登录后 Cookie 能管几小时到几天，那几小时的爬取完全不需要碰验证码。

Tesseract OCR

Tesseract 是一个 OCR 库，目前由 Google 赞助。Tesseract 是目前公认最优秀、最精确的开源 OCR 系统，除了极高的精确度外，Tesseract 也具有很高的灵活性，可以通过训练识别出任何字体（只要风格统一），也可以识别出任何 Unicode 字符。

安装：

平台 命令 / 操作

2）降噪（depoint）——去掉孤立的小黑点：

这两个函数的逻辑非常朴素，但非常通用：

  • 二值化：一个字如果笔画够黑，那么"比阈值暗的保留、比阈值亮的丢掉"就能把字和底分干净；
  • 降噪：一个孤立的黑点，它周围应该大多是白色；如果八邻域里白色超过一半（>4），那它就不像笔画（笔画是连续的），抹掉。

课件里给了两个测试站（imcta.cn 测二值化、i.djye.com 测二值化 + 降噪）。调参思路：二值化的阈值先试 140 左右，太黑丢笔画、太白留噪点，多试几次取识别最好的。

八、合规提醒（课件之外，但很重要）

技术讲完了，这一段是我自己补的，建议在写第一个真实爬虫之前先读一遍：

  1. 先看 robots.txt——它写明了站点不希望被爬取的部分，尊重它是基本礼貌；
  2. 控制频率——加 time.sleep()，别让并发打满对方服务器。把对方爬挂不是技术成就，是事故；
  3. 不要抓取和传播个人信息、隐私数据、付费内容——这可能触碰《个人信息保护法》与《数据安全法》；
  4. 不要用于商业竞争性用途——抓取对方数据做同类产品，法律风险很高；
  5. 不要绕过登录/付费去获取非公开数据——涉及"非法获取计算机信息系统数据"的风险。

一句话：爬公开数据、控制频率、遵守 robots、不碰隐私和付费内容。技术上做得到，不等于法律上可以做。

小结

  1. 反爬和反反爬是一场"成本博弈"：对方抬高成本，我们降低自己被抓的概率——限制频率永远是第一优先级；
  2. 代理 IP 三类（透明/匿名/高匿），爬虫常用私密代理；proxies 字典 http 与 https 要分别配，必须带 timeout；
  3. 动态页面抓的是接口不是页面：F12 的 Network 里过滤 XHR，按"清空 → 操作 → 看新请求"的顺序找，六步套路是标准流程；
  4. headers 三件套：UA（用 UA 池随机拼装）、Referer（带上来源）、Cookie（首选 requests.session() 模拟登录）；
  5. 验证码的性价比排序：手动登录一次 + Cookie 复用 > 打码平台 > 百度 OCR / Tesseract；Tesseract 前先做二值化 + 降噪，识别率会明显提升；
  6. 合规比技术更容易出事——robots、频率、隐私、付费内容，四条线都不要越。

爬虫系列回顾

五篇走下来，正好是一条完整的学习路径：

篇目 解决的问题
爬虫入门：原理与抓包 搞清楚数据在哪、怎么被浏览器拿到

爬虫解析与存储 BeautifulSoup / JSONPath 解析，文件/CSV/MySQL 存下来
爬虫进阶：XPath 与 Fiddler 定位更刁钻的节点、抓非浏览器流量
