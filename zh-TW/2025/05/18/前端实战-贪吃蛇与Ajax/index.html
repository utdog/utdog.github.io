前端实战：贪吃蛇与 Ajax

前言

上一篇把 JS 的语法、DOM、对象都过了一遍。这一篇是前端课件的收官：先把前面学的对象、原型、数组、定时器、键盘事件串成一个真正的项目——贪吃蛇；再学一个让页面"不用刷新就能拿数据"的技术——Ajax。

课件 day22 的案例里，老师的原话是"我会完全按照工作里面模块化开发的思想来写"。所以这两块正好代表了前端开发的两条主线：页面里的逻辑怎么组织，和页面怎么跟服务器说话。

说明：day22 同样没有 笔记 目录，以下代码与结论均整理自案例文件（02-自执行函数.html、03贪吃蛇项目.html、04-Ajax.html、05-完整版Ajax.html、06-jq的ajax请求数据.html）。

二、贪吃蛇：Food 模块

食物的本质是地图上一个 20×20 的小方块 div，位置随机但要对齐网格。

两个关键点：

  1. 随机位置必须对齐网格：先算出地图能放下多少列（scope.offsetWidth / this.width），取一个随机整数列号，再乘回方块宽度。直接随机像素值的话，蛇头永远碰不到食物。
  2. remove() 为什么用数组：因为食物被吃掉后要"再出现一个"，用数组保存所有食物 dom，删除时循环 removeChild + splice。

这段是为了讲解才写成循环的，实际 play 时数组里最多一个元素。如果真要删一堆，倒着循环 for (let i = arr.length - 1; i >= 0; i--) 更安全——正着删会因为 splice 改变下标而漏掉元素（下面的 removeSnake 就踩过这个坑，所以它是倒着写的）。

五、Ajax：不刷新页面也能拿数据

Ajax = Asynchronous JavaScript And XML（异步的 JavaScript 和 XML）。它的核心优势是：不用等整个页面重新加载，就能从服务器拿到数据。

课件列的四个优点：

  1. 不需要插件支持（浏览器原生就有）；
  2. 用户体验极佳（页面不闪、不跳）；
  3. 提高了 Web 性能——可以局部发送请求，不用请求整个页面；
  4. 减轻服务器的压力和带宽负担。

原生写法：四步

readyState 有五个状态：

值 含义
0 请求未初始化（还没调用 open()）
1 请求已经建立（还没调用 send()）
2 请求已经发送
3 请求正在处理
4 响应完成，可以获取并操作后台数据了

onreadystatechange 会在这几个状态变化时反复触发，所以必须判断 readyState == 4，否则会在数据还没回来时就渲染，页面上是一片空白。

完整版：还要判断 HTTP 状态码

状态码 含义
2xx 成功（200 成功接收了数据）
3xx 重定向（304 表示用了缓存）
4xx 客户端问题（404 文件找不到）
5xx 服务器问题（500 后台报错）

readyState == 4 只代表"请求走完了"，不代表"成功"——服务器返回 404、500 时它也是 4。所以真正的判断是两层：readyState 看流程，status 看结果。

六、踩坑速查

现象 原因 解决
Cannot read properties of undefined 定时器回调里 this 指向 window，不是实例 提前 let that = this，或用箭头函数
渲染出来一片空白 没判断 readyState == 4 在状态为 4 时再操作数据
请求 404/500 但代码没报错 只判断了 readyState，没判断 status 再加一层 status 判断
JSON.parse 报 Unexpected token 数据本身不是合法 JSON 检查键名双引号；先 console.log 看原始数据
Uncaught SyntaxError + 中文乱码 文件编码不是 UTF-8 加 <meta charset="UTF-8">，编辑器另存为 UTF-8
删除数组元素时漏删 正序循环里 splice 改变了下标 倒序循环 for (let i = arr.length - 1; i >= 0; i--)
食物随机位置永远吃不到 随机到了像素值，没对齐网格 先取随机列号再乘格子宽
换了方向马上撞自己 一帧内连续按键改变方向 加方向校验 / 限制每帧只响应一次
请求发不出去（跨域报错） 浏览器同源策略 开发时让后端加 CORS 响应头，或用代理

小结

自执行函数 + 构造函数 + 原型 = 一个可以拆模块的小项目。贪吃蛇只有三件事：食物在网格上随机出现、蛇按"尾随头"往前走、游戏循环用 setInterval 驱动加键盘改方向。坐标用格号不用像素，是这个项目最舒服的一个设计。

Ajax = XMLHttpRequest + 状态判断 + 数据转换。原生四步（new → open → send → onreadystatechange）看清原理，实际写的时候用 jQuery 的 $.get 或 $.ajax 省事。判断成功要两层：readyState == 4 说明流程走完，status 在 200–304 才说明结果 OK。

回头看这一套前端课件：从 HTML 标签 → CSS 选择器与布局 → 原生 JS 语法与 DOM → 对象与原型 → jQuery 与 Bootstrap → 一个完整项目和 Ajax 交互，这条线走完，一个静态页面的所有技能点就齐了。再往后就是后端（Django 部分已经写过三篇）和爬虫。

说明：本文依据课件 day22 的五个案例文件整理，代码片段为案例中的原始写法（含 let that = this、parseInt 等"当时的写法"），箭头函数为什么能避免 this 问题、倒序删除、跨域 那几处是我补充的说明。
