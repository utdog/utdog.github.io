爬虫入门：原理、HTTP 与抓包

前言

Django 那几篇讲的是"怎么把数据端出去"，爬虫正好反过来——怎么把别人网页上的数据拿回来。

拿到数据是数据分析、机器学习的第一步。课件里有个很实在的说法：中小公司拿数据的四条路（买、下载、爬、人工收集）里，爬虫是成本最低、质量最可控的一条。

这篇先把地基打好：爬虫是什么、HTTP 到底怎么交互、以及怎么用浏览器的开发者工具找到我们真正要请求的那个地址。后面所有爬虫代码，都是这三件事的重复。

说明：本文依据课件《03-爬虫课件-全栈开发班 / 1.爬虫基础入门》的四份笔记（爬虫介绍、爬虫的分类及原理、http 和 https 的请求与响应、chrome 浏览器抓包说明）整理，结尾的合规部分是我自己补充的。

一、什么是爬虫

网络爬虫（又称网页蜘蛛、网络机器人）是一种按照一定的规则，自动地抓取万维网信息的程序或者脚本。

拆开看两个关键词：自动（不用人点）和一定的规则（爬什么、爬到什么程度，由我们写代码时定）。

最典型的爬虫就是搜索引擎的爬虫。百度搜索引擎的爬虫叫百度蜘蛛（Baiduspider），它每天在海量互联网信息里爬取、收录优质页面；用户在百度搜索关键词时，百度对关键词做分析处理，从已收录的网页里找出相关的，按排名规则排序后展示。

所以"我的博客为什么没被百度收录"这类问题，本质上是百度蜘蛛有没有爬到、爬到了之后给了多少权重的问题——这也是"访问权重"这个词的由来。

原则上，只要是浏览器（客户端）能做的事情，爬虫都能做——课件里叫"万物皆可爬，可视即可爬"。能抓的数据包括：

  • 网页文本（标题、正文、评论……）
  • 图片
  • 视频、音频
  • 其他：只要能请求到，就意味着能获取到

爬虫的领域

数据从哪来？课件列了四条：去第三方公司买（比如企查查）、去免费数据网站下载（比如国家统计局）、通过爬虫爬取、人工收集（问卷调查）。人工费时费力，免费网站数据质量不佳，而第三方数据公司的数据往往也是爬来的——所以爬虫是最有效的途径。

应用领域：

  • 人脸识别：训练模型需要几千万甚至几十亿张人脸图片，这些图片不可能靠人工收集，只能靠爬虫建库；
  • 市场分析：电商分析、商圈分析、一二级市场分析；
  • 市场监控：电商价格、新闻舆情、房源监控；
  • 商机发现：招投标情报、客户资料、企业客户发现；
  • 后面学到数据分析，还能爬金融股票数据做分析（课件原话叫"技术型炒股"）。

像百度指数、微博热搜、阿里指数、360 指数，原理都是统计自己用户的搜索/访问数据。中小公司没有这么大的用户量，那就只能靠爬虫去采集公开数据。

爬虫等于黑客吗？

课件的观点很明确：技术和工具是同一套，区别在目的和行为性质。

黑客 爬虫
目的 非法入侵、破坏数据 采集公开、开放的数据
行为 删库、改库、获取隐私 抓页面文本、图片
性质 违法 合法（在合规前提下）

就像菜刀——有人拿去切菜，有人拿去伤人，菜刀本身没有好坏。但正因为工具相同，写爬虫的人必须清楚边界在哪里。

robots 协议（课件放在"了解"里）：网站在根目录放一个 robots.txt，告诉爬虫哪些页面可以抓、哪些不可以。比如我的博客 source/robots.txt 就是干这个的。但要记住课件那句提醒——robots 协议仅仅是道德层面的约束，它不拦你，拦你的是法律和反爬技术。

二、爬虫的分类

按系统结构和实现技术，大致分四类：

类型 说明 例子
通用网络爬虫 从整个互联网搜集网页、采集信息，为搜索引擎建索引 百度蜘蛛
聚焦网络爬虫 也叫主题爬虫，目标网页定位在与主题相关的页面中，先筛选再抓取，节省资源和带宽 比价网站
增量式网络爬虫 只爬内容发生变化的网页或新产生的网页（增量式更新） 招聘网爬虫
深层网络爬虫 爬那些必须提交表单/关键词之后才能到达的"深层页面" 需要搜索才出结果的站

课件特别强调：后面主要学聚焦爬虫，聚焦爬虫学会了，其他类型也就能写出来。

通用爬虫 vs 聚焦爬虫的原理

通用爬虫四步：

  1. 抓取网页：start_url 发送请求 → 获取响应并解析 → 把解析出的新 URL 放进待抓取 URL 队列 → 取出一个，解析 DNS 得到主机 IP，把网页下载下来存进已下载网页库，同时把该 URL 放进已抓取 URL 队列 → 继续从已抓取队列里分析出新的 URL 进入下一个循环；
  2. 数据存储：把爬到的网页存入原始页面数据库，里面的页面数据和用户浏览器看到的 HTML 完全一样。同时会做重复内容检测——如果一个权重很低的网站上全是抄袭、采集来的内容，蜘蛛很可能就不爬了；
  3. 预处理：提取文字、中文分词、消除噪音（版权声明、导航条、广告）、索引处理、链接关系计算、特殊文件处理。除了 HTML，还能抓 PDF、Word、WPS、XLS、PPT、TXT；但图片、视频、Flash 这类非文字内容处理不了，也不能执行脚本和程序；
  4. 提供检索服务 + 网站排名。

聚焦爬虫的步骤更简单，而且更贴近我们要写的东西：

通常把"获取响应"和"解析"放在一步里完成，所以通俗讲就是四步：发请求 → 拿响应 → 解析提取 → 保存。

这四个字后面会重复出现在每一篇爬虫文章里——不管用的是 Requests、BeautifulSoup 还是 XPath，都是在做这四步中的某一步。

三、HTTP 与 HTTPS

HTTP HTTPS
全称 HyperText Transfer Protocol（超文本传输协议） HTTP over Secure Socket Layer
说明 发布和接收 HTML 页面的方法 HTTP 的安全版，在 HTTP 下加入 SSL 层
默认端口 80 443

SSL（Secure Sockets Layer 安全套接层）在传输层对网络连接进行加密，保障数据传输安全。

浏览器发送 HTTP 请求的过程

  1. 在地址栏输入 URL 并回车，浏览器向 HTTP 服务器发送请求（请求主要分 Get 和 Post 两种方法）；
  2. 浏览器请求 http://www.baidu.com 的 html 文件，服务器把 Response 文件对象发回来；
  3. 浏览器分析 Response 中的 HTML，发现引用了图片、CSS、JS 等文件，自动再次发送请求去拿这些文件；
  4. 所有文件下载成功，网页按 HTML 语法结构完整显示出来。

第 3 步很关键：打开一个网页，浏览器发的不是一次请求，而是一串请求。这也是抓包时"一堆请求"的来源——大部分是 js、css、图片，真正关心的一般只有第一个。

URL 的结构

部分 含义
scheme 协议（http、https、ftp）
host 服务器的 IP 地址或者域名
port# 端口，走默认端口时可省略（http 缺省 80）
path 访问资源的路径
query-string 参数，发送给服务器的数据
anchor 锚，用于页面内跳转

例子：http://item.jd.com/11936238.html#product-detail。

GET 与 POST

GET POST
作用 从服务器获取数据 向服务器传送数据
参数位置 拼在 URL 里，在浏览器地址栏可见 在请求体（body）中，隐式发送
长度限制 受 URL 长度限制 消息长度没有限制
典型场景 搜索、翻页 登录、表单提交、文件上传

GET 的例子：http://www.baidu.com/s?wd=Chinese——参数 wd=Chinese 就是 URL 的一部分。

POST 的参数包含在请求体的 Content-Type 消息头里，指明消息体的媒体类型和编码。POST 通常用来提交量比较大的数据（参数很多或者文件上传）。

课件特别提醒：避免用 GET 提交表单。比如登录表单用 GET，用户输入的用户名和密码就直接暴露在地址栏里了。

爬虫视角的推论：一个接口是 GET 还是 POST，决定了我们要把参数放在 params 还是 data 里——这是写 Requests 代码时要看的第一个信息。

四、请求报头与响应报头

常用请求报头（11 个）

报头 作用
Host 指定被请求资源的 Internet 主机和端口号，通常是 URL 的一部分
Connection 连接类型。HTTP/1.1 默认 keep-alive，能重用连接，减少资源消耗、缩短响应时间
Upgrade-Insecure-Requests 把加载的 http 资源自动替换成 https 请求，避免 https 页面里的 http 请求告警
User-Agent 客户浏览器（客户端）的名称——爬虫伪装最常用的一项
Accept 客户端可以接受的 MIME 文件类型
Referer 产生请求的页面来自哪个 URL。防盗链就是靠它判断的
Accept-Encoding 可以接受的编码方式（如 gzip），用于压缩传输、加速
Accept-Language 可以接受的语言种类（en、zh-cn……）
Accept-Charset 可以接受的字符编码（ISO8859-1、gb2312、utf-8）
Cookie 向服务器发送 Cookie，实现会话功能
Content-Type POST 请求里表示请求体的内容类型和编码

几个细节值得记住：

  • Accept 的 q 值：Accept: text/html, application/xhtml+xml;q=0.9, image/*;q=0.8 里的 q 是权重系数，范围 0 ≤ q ≤ 1，值越大越倾向接受该类型；不写默认是 1，写 0 表示不接受。
  • Referer 与防盗链：下载某些网站的图片必须带对应的 referer，否则拿不到——原理就是人家靠 referer 判断请求是不是从本站发起的。
  • Accept-Encoding 与乱码：服务器可能返回 gzip 压缩的内容，客户端要先解码再检查文件格式。

服务端响应：四个部分

状态行、消息报头、空行、响应正文。一个真实的响应长这样：

常用响应报头

报头 含义
Cache-Control 缓存策略。no-cache 表示下次必须重新向服务器请求；max-age=86400 表示 86400 秒内可直接用缓存
Connection 回应客户端的 keep-alive，告诉它可以继续用这个 TCP 连接发请求
Content-Encoding 说明资源用了哪种编码（如 gzip），客户端要相应解码
Content-Type 资源类型 + 字符编码。网页乱码往往就是服务器没返回正确编码
Date 服务端发送资源的时间，HTTP 协议中的时间都是 GMT，避免时区混乱
Expires 与缓存有关，告诉客户端在这个时间前可以直接用缓存。不如 Cache-Control: max-age 准确，因为它依赖客户端和服务器时间一致
Pragma 含义与 Cache-Control 等同
Server 服务器和对应的版本
Transfer-Encoding: chunked 分块发送。用于服务器动态生成、发送时还不知道大小的资源，每块自带长度，最后一块长度为 0
Vary 告诉缓存服务器缓存压缩和非压缩两个版本（现在用处不大）

Cookie 与 Session

服务器和客户端的交互仅限于请求/响应过程，结束之后连接断开，下一次请求服务器会认为这是一个新的客户端。为了维护这个"链接"，让服务器知道这是上一个用户发来的请求，必须找地方保存客户端信息：

  • Cookie：通过在客户端记录的信息确定用户身份；
  • Session：通过在服务器端记录的信息确定用户身份。

爬虫的实际意义：如果要抓登录之后才能看的数据，核心就是把登录成功后的 Cookie 带上。课件后面讲用 CookieJar 和 requests.Session() 保持登录，原理就在这里。

响应状态码

三位数字，第一位定义类别：

区间 含义
100~199 服务器成功接收部分请求，要求客户端继续提交其余请求
200~299 成功接收并完成处理，常用 200（OK）
300~399 需要进一步细化请求，如资源移动了新地址：302（临时转移）、307、304（使用缓存）
400~499 客户端请求有错：404（找不到页面）、403（拒绝访问，权限不够）
500~599 服务端错误，常用 500

五、同步加载、异步加载与网页源码

判断一个页面好不好爬，先看它是哪种加载方式：

  • 同步加载：改变网址上的请求参数会导致网页改变。例如 www.itjuzi.com/company?page=1，把 page= 后面的数字改掉，网页内容跟着变；
  • 异步加载：改变网址参数网页不变。例如 www.lagou.com/gongsi/，翻页后网址没变化——数据是 Ajax 异步请求回来的。

异步加载意味着我们不能只请求地址栏那个 URL，得去抓包找到真正的数据接口（通常返回 JSON）。这是爬虫新手最容易卡住的地方。

网页源码由三部分组成：

  • html：描述网页的内容结构；
  • css：描述网页的排版布局（课件提到"高深的反爬"就用 css，比如用 CSS 伪元素把数字替换掉）；
  • JavaScript：描述网页的事件处理（鼠标、键盘动作后的程序）。

六、Chrome 抓包

目标：掌握 Chrome 在爬虫中的使用。 右键 → 检查（或 F12）→ Network → 刷新页面。

1. 新建无痕窗口

作用：第一次请求某个网站时没有携带 Cookie，和代码请求一个网站的状态一致。这样就能尽量还原代码请求的结果——除非数据是通过 js 加密加载出来的，否则爬虫请求到的数据和浏览器请求到的大部分时候是相同的。

这是个很实用的小技巧：代码爬不到数据时，先用无痕窗口访问一次。如果无痕窗口里也没有数据，说明需要登录态，而不是你的代码写错了。

2. Network 的常用功能

功能 说明
Preserve log 默认情况下页面跳转后之前的请求记录会消失，勾选后保留全部请求（登录跳转、翻页场景必开）
Filter 过滤 URL 很多时，在 filter 框里输入部分地址做过滤
请求类型筛选 All 全部；XHR 大部分情况表示 Ajax 请求；JS；CSS
Search all file 全局搜索文件内容
确定 js 文件位置 找到相关的 js（分析加密参数时用）
在 js 中打断点 调试 js 的执行过程

课件有句话很安慰人：不要被浏览器里一堆请求吓到，除了 js、css、图片请求外，其他请求并没有多少个。而且拿不准需要的请求是什么类型时，直接选 All 从前往后看即可。

3. 抓包怎么看

通常我们抓的第一个包，就是访问这个 URL 地址的响应。点开它：

  • Headers：包含了请求携带的请求头、响应头等信息。爬虫遇到反爬时，就通过查看这里判断自己缺少了哪些请求信息，补上即可；
  • Response：请求这个 URL 得到的响应，通常是页面源码或者 JSON 数据。

4. 寻找登录接口

找登录接口有两条路：

（1）看表单的 action

登录页的 <form> 标签上通常有 action 属性，那就是提交的 URL 地址——回顾前端知识，它就是表单提交的地址。提交的数据也很直白：

用户名 input 标签中 name 的值作为键，用户名作为值；密码 input 标签中 name 的值作为键，密码作为值。

（2）通过抓包找

有些网站的 action 没有 URL，或者参数是被 js 加密的。这时抓包看请求就能发现：URL 地址和请求体中都会带参数，比如人人网的 uniqueTimestamp、rkey，以及加密之后的 password。

课件给了个很聪明的思路：同一个网站的手机版登录接口往往参数更少，可以拿手机版作为参照来学习怎么分析 js。

遇到加密参数，一般就是三件事：找到加密的 js 文件 → 读懂它做了什么（常是 MD5、时间戳拼接之类）→ 在 Python 里用同样的算法算一遍。这一块属于 JS 逆向，课件里没有展开讲。

七、踩坑与合规提醒

现象 原因 思路
抓不到数据，页面是空的 数据由 Ajax 异步加载 抓 XHR 请求，直接请求接口
代码请求返回的内容和不登录时不一样 需要 Cookie / Session 带上登录后的 Cookie
图片/文件下载 403 防盗链，检查 Referer 请求头里补上 Referer
返回内容乱码 编码不对（gb2312 / utf-8 / gzip） 看 Content-Type，必要时设 response.encoding
请求被拒绝、返回验证码页 触发了反爬 看 User-Agent、频率、有无签名参数
页面跳转后请求记录丢了 没勾 Preserve log 勾上再操作

最后说几句课件里点到、但值得展开的合规边界（这部分是我自己的补充）：

  1. 只爬公开数据，不碰个人隐私和需要授权的数据；
  2. 看 robots 协议，它虽然只是道德约束，但违反它会成为"具有主观恶意"的证据；
  3. 控制频率，别把对方站点打挂——这既是礼貌，也是最容易踩法律红线的地方；
  4. 不要绕过技术保护措施去获取"明确不希望你获取"的数据（比如破解付费墙、批量抓取用户信息）；
  5. 国内要留意《网络安全法》《数据安全法》《个人信息保护法》，以及侵犯公民个人信息罪和非法获取计算机信息系统数据罪这两个具体罪名。

一句话总结：技术上能爬不等于法律上能爬。写爬虫之前先问自己一句：“这些数据如果对方知道了我在批量抓，会不会来找我？”

小结

这一篇没有一行代码，但它是后面所有爬虫文章的地基：

  1. 爬虫 = 模拟客户端发送网络请求 + 接收响应，只要能请求到就能获取到；
  2. 聚焦爬虫四步：发请求 → 拿响应 → 解析提取 → 保存数据；
  3. HTTP 交互要看三类信息：URL 结构、请求头（尤其是 User-Agent、Referer、Cookie）、响应状态码与编码；
  4. 抓包是爬虫的"眼睛"：无痕窗口还原未登录状态、Preserve log 保留跳转记录、XHR 快速定位异步接口、Headers 对比补齐请求头。

下一篇进入实战：Requests 库与正则表达式——把今天说的请求头、参数、Cookie 真正写进 Python 代码里。
