爬虫进阶：Requests 库与正则表达式

前言

上一篇把原理讲完了，聚焦爬虫就四步：发请求 → 拿响应 → 解析提取 → 保存数据。

这一篇覆盖前两步和第三步的前半截：

  • Requests 负责"发请求、拿响应"——把上一篇讲的请求头、参数、Cookie 真正写进代码；
  • 正则表达式负责"解析提取"里的第一步——从字符串里把需要的内容抠出来。

说明：本文依据课件《2.爬虫核心技巧》的两份笔记（《1.HTTP请求库和Requests详解》《2.正则表达式详解》）整理，代码与案例都来自课件。正则语法速查表和踩坑表是我自己的补充。

一、为什么用 Requests

Requests 是用 Python 语言编写，基于 urllib，采用 Apache2 Licensed 开源协议的 HTTP 库。

课件给它的评价是"Requests 唯一的一个非转基因的 Python HTTP 库，人类可以安全享用"——这是官方文档里那句著名的玩笑（“HTTP for Humans”）。

它比 urllib 好在哪：

  • 底层就是 urllib，但 API 友好得多，不用手写 Request 对象和 urlopen；
  • 自动处理编码、自动解压 gzip；
  • 支持 HTTP 长连接和连接池；
  • 支持 Cookie 保持会话、文件分块上传、自动确定响应内容编码；
  • 国际化和域名支持良好；
  • Python 2 和 Python 3 都能用。

带参数的 GET：百度搜索

两个要点：

  1. params 会自动做 URL 编码，中文、空格、特殊字符都不用自己 urlencode；
  2. res.url 能看到最终请求的完整地址——课件特别提醒过它和直接请求 www.baidu.com/s?wd=Chinese 是有区别的，区别就在那串 http%3A%2F%2F 的编码上。

二、response 的五个常用属性

属性 含义
response.text 返回文本形式的响应内容
response.content 返回二进制形式的响应内容
response.url 请求的最终 URL（会跟着重定向走）
response.encoding 从 HTTP 报头中获取的响应内容编码方式
response.status_code 响应状态码
response.json() 把返回的 JSON 字符串反序列化成 Python 对象（前提是返回的确实是 JSON）

乱码是怎么来的（很关键的坑）

课件用新浪做过实验：有些网页用 response.text 取回来是乱码。原因有两条：

  1. 网络上的大部分服务器都启用了 gzip 压缩——requests 会在请求头里带上 Accept-Encoding: gzip，拿到的内容是压缩的，不是明文；requests 能自动解压，这一步通常不用我们操心；
  2. 真正的坑在编码判断：response.text 会尝试用 HTTP 响应头里的编码去解码；如果对方没给或者给错了，requests 就会用 chardet 去猜，猜错就乱码。

对"文字"用 response.text，对"图片/视频等二进制"用 response.content。遇到乱码时，课上给的解法是直接指定编码解码：

顺带一个实用推论：抓图片、验证码这类文件时用 content 拿二进制，再用 open(..., 'wb') 写进文件，不能用 text。

别急着解析 HTML

课件里有句话值得记住：用 response.text 打印出来的一大坨 HTML，绝大部分是我们不需要的——真正要的三个数据可能藏在一万行里。这就是"解析提取"存在的理由，也是下一篇 BeautifulSoup 和 XPath 要解决的问题。

data 传 JSON 的情况

课件还给了快手的例子：抓包看它的请求体是一串 JSON 而不是表单。这时有两种写法：

  • 把 data 设置成符合 JSON 格式的字符串（json.dumps(...)）；
  • 直接用 json= 参数传字典，requests 会自己序列化并带上 Content-Type: application/json。

同时要在 headers 里补上对应的 Content-Type。规律是：抓包的请求体长什么样，我们的 data 就长什么样。

四、代理与认证

代理（proxies）

要点：

  • http 和 https 可以分别指定，要按请求的协议去取对应的那一项；
  • 如果代理需要账号密码：http://user:pass@host:port/**（私密代理的写法）；
  • 代理也可以走环境变量（HTTP_PROXY / HTTPS_PROXY），用 proxies 参数会覆盖环境变量；
  • 用代理的目的主要是应对 IP 被封（反爬）与隐藏真实来源。

Web 客户端验证（auth）

这是 HTTP 基础认证（服务端返回 401 并要求认证时的用法），和表单登录不是一回事。

五、Cookie 与 Session

先把概念钉死：

  • Cookie：通过在客户端记录信息确定用户身份；
  • Session：通过在服务器端记录信息确定用户身份。

Cookie 的限制（课件原话）：每个 Cookie 不超过 4K；一个服务器最多在客户端浏览器上保存 20 个 Cookie；一个浏览器最多保存 300 个 Cookie。 并且因为 Cookie 存在客户端，可以被分析和欺骗，安全性较差。

爬虫为什么关心它：一套 Cookie 在服务器那边就代表一个用户。所以：

  • 好处：把登录后的 Cookie 带上，就能抓"登录后才能看"的数据；
  • 坏处：一个用户短时间内请求太频繁，很容易被识别成爬虫——所以大规模采集要靠多账号轮换 Cookie。

保持会话：requests.session() 的意义

课上有一句总结很到位：

如果用 requests.get() 请求，每次请求都相当于新开了一个浏览器，上一次请求的 Cookie 不会被带上；requests.session() 则是同一个浏览器，能保持参数（Cookie）和长连接。

六、正则表达式

为什么爬虫必须会正则

爬虫四步里的第三步叫"解析提取"，课件把它拆成：

  1. 明确目标：要抓什么字段；
  2. 抓取页面：Requests 负责；
  3. 提取数据：从 HTML/JSON 里把字段抠出来——这一步就是正则、BeautifulSoup、XPath 的舞台；
  4. 处理数据：清洗、入库。

正则是什么

正则表达式是对字符串操作的一种逻辑公式，就是用事先定义好的一些特定字符、及这些特定字符的组合，组成一个"规则字符串"，这个"规则字符串"用来表达对字符串的一种过滤逻辑。

它在爬虫里的用法非常具体："匹配"和"替换"符合某种模式的文本。比如从一整页 HTML 里匹配出所有 href="..." 里的链接。

课件列了两条使用原则，非常实用：

  • 能不能用字符串函数解决？能就别用正则——能用 str.find、split 完成的事，用正则是自找麻烦；
  • 正则的匹配效率不高，正则越长越复杂，性能越差。

原始字符串与 compile

写正则一定要用原始字符串 r''：不加 r 时，'\d' 虽然恰好没被 Python 转义，但 \b、\n 这些会；加了 r 就明确告诉 Python"这一串里的反斜杠不是转义符，交给 re 模块解释"。

re.compile() 是把"规则字符串"编译成一个 Pattern 对象，可以反复用（爬虫里循环几千次时能省下重复编译的开销）。

findall 匹配所有符合规则的 列表
finditer 匹配所有，返回迭代器 迭代器
split 按正则切分成列表 列表

findall

一次把所有匹配结果取成列表，爬虫里最常用。没有匹配到就是空列表 []——这个判断很有用：if not result: 说明没抓到，可能是结构变了或者被反爬了。

sub 替换

sub 的完整签名是 sub(repl, string, count=0)：repl 可以是字符串，也可以是函数（函数的返回值就是替换后的内容）；count 不填默认全替换，填了就是最多替换几次。

贪婪与非贪婪（最容易写错的地方）

课件的例子非常典型。有一串 <div>python</div><div>hello</div>，如果我们想匹配出 python：

原因：Python 里的数量词默认是贪婪的——.* 会尽可能多地往后吃，一直吃到最后一个 </div>；而 .*? 是非贪婪（也最小匹配），碰到第一个 </div> 就停。

再把它讲透一层：

写法 匹配过程 结果
<div>.*</div> <div> 之后一路狂吃到字符串末尾，再往前回退找 </div> 一个超长的匹配
<div>.*?</div> 先试展开 0 个字符，不满足就往后一个一个字符试，遇到 </div> 立即收工 每个 <div> 各匹配一次

所以在 HTML 里匹配标签，几乎总是要加 ?。课件里这类"贪婪导致匹配错位"的坑，是被单独列出来强调的。

小结

  1. Requests 就是"用代码当浏览器"：get/post 对应取/送，参数用 params 还是 data 由抓包决定；
  2. 默认 UA 会出卖你，正式爬虫第一件事就是补 headers；
  3. text 看文字、content 收二进制，乱码就用 content.decode() 自己定编码；
  4. 要登录态就用 requests.session()，它替你保管 Cookie；
  5. 正则是字符串层面的过滤器：match 从头部、search 找任意位置、findall 取全部、sub 做替换，写 HTML 匹配记得加 ?。
