前言

上一篇把函数讲到了装饰器，这篇解决另一个问题：代码怎么组织。

单个 .py 文件从几十行写到几百行之后，全堆在一起就没法维护了。Python 的答案是「模块」和「包」——把功能拆到不同文件里，需要的时候导入。课件 day-14模块与包 讲组织方式，day-15常用模块 讲五个必须会用的内置模块，两天的笔记合成这一篇。

一、模块：一个 Python 文件就是一个模块

三个东西的容量是层层放大的：

单位 能装什么
变量 一个或多个数据
函数 有功能的多行代码
模块 变量、函数，什么都能装

导入一个模块之后，就能用它里面的变量和函数。

模块分三类

类型 说明 例子
内置模块 Python 自带，不用下载，导入即可用 time、random
第三方模块 别人开发好的，必须先下载 pygame（游戏）、requests（爬虫）
自定义模块 我们自己写的 .py 文件 text.py

PyCharm 里也可以图形化安装：File → Settings → Project → Project Interpreter → 右侧 + 号 → 搜索模块名 → Install。

几个导入习惯

from ... import ... 的弊端是容易和自己的变量同名，同名时模块里的内容会被覆盖。所以使用顺序是：先导入 → 再调用 → 优先用自己的 → 最后才用模块里的。

（补充：import time, random 这种一行导入多个模块语法本身是合法的，课件不建议只是为了可读性。）

导入模块时，解释器做了什么

  1. 把模块里的全部内容读取一遍，确保没有异常；
  2. 生成一个名称空间，名字和模块名一致；
  3. 等待程序调用：模块名.变量名 / 模块名.函数名()。

三、__name__：这个文件是程序还是模块

Python 用 __name__ 属性来区分：

于是有了这个到处都能见到的写法：

三条要点：

  1. 别和别的语言的 main 搞混，性质不一样；
  2. __name__ 是 __main__ 就是启动程序，否则是模块；
  3. 把「只有作为程序运行才需要」的代码放进这个判断里。

在 PyCharm 里输入 main 按回车/Tab 就会自动生成这段。它通常写在文件最后——既整洁，也能确保前面用到的函数、变量都已经定义好。模块里加这段更多是为了测试模块中的代码能否正常跑。

另外 __file__ 可以拿到文件所在的位置。

四、包：管理模块的特殊文件夹

在 PyCharm 里 New → Python Package 创建，会自动生成一个 __init__.py：

  • __init__.py 负责管理包里的模块；
  • 导入包的时候，它里面的内容会自动执行；
  • 可以在里面写这个包的使用说明或注意事项。

看不懂某个功能在哪定义？按住 Ctrl 把鼠标放到函数名上点一下，直接跳到它的源码。

十、json：保留类型地存数据

先看不用 json 的问题：

json 解决的问题就是：存进去是列表，取出来还是列表。

四个功能，两两一对：

功能 方向 作用
dumps 序列化 数据类型 → 字符串
dump 序列化 数据类型 → 字符串并写入文件
loads 反序列化 字符串 → 数据类型
load 反序列化 从文件读取 → 数据类型 
flowchart LR
    A["Python 数据
列表 / 字典 / 数字"] -->|"dumps / dump"| B["JSON 字符串
序列化后的文本"]
    B -->|"loads / load"| A

序列化就是计算机底层认识的机器码，反序列化是人能看懂的形态。json 支持几乎所有数据类型，只有两个例外要注意：集合（set）不支持；None 会被转成 null，意思都是空。

十一、踩坑表

坑 现象 正确做法
模块名带后缀 import text.py 报 ModuleNotFoundError 导入时只写模块名 import text
模块名用大小写/驼峰 别人导入容易出错 全小写，多词用下划线，如 user_login
from 模块 import x 与自己的变量重名 模块里的内容被覆盖 优先用自己的；需要时改用 import 模块
忘了先下载第三方模块 ModuleNotFoundError: No module named 'requests' 先 pip install，国内加 -i 镜像
把 if __name__ == '__main__': 写错成 = 判断永远为假/语法错 比较运算符是两个等号
以为导入包会执行 __init__.py 里的所有功能 只想写说明却执行了代码 __init__.py 里放轻量内容或说明
open 打开后忘了 close 文件被占用、内存泄漏 用 with open(...) as f: 自动关闭
w 模式打开已有文件 原内容被清空 追加用 a 模式
json.dump 分多次写同一个文件 json.load 报 Extra data 攒好数据后一次写，或改用 JSON Lines 逐行读
json 存了 set TypeError: Object of type set is not JSON serializable 先转成 list 再存
